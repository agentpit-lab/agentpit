Getting started with dbWise

dbWise gives an agent access to PostgreSQL databases at three levels: read, diagnose and write. Every alias has a level and its own logins, and at read and diagnose dbWise checks the database role behind each login.

TL;DRInstall the plugin, add one alias at read with its own database login, and run dbwise doctor. Raise the alias to diagnose only when the agent should read plans and index advice, and give that level a login of its own.

Install

  1. Install the plugin

    /plugin install dbwise@agentpit

    The marketplace is agentpit. The install adds the MCP server plugin:dbwise:postgres, the /dbwise:config and /dbwise:doctor skills, and the dbwise command, which is on the PATH of the agent's Bash tool.

  2. Start a session

    The first start builds the server's Python environment and needs a route to PyPI. Until it finishes, the server offers a single dbwise_status tool that says what it is waiting for.

  3. Check the server

    /mcp

    Open the list of servers. `plugin:dbwise:postgres` should be connected. The server reads its configuration once, when it starts, so reconnect it after every change to the configuration.

One alias at read

An alias is the name the agent uses in a tool call. It points at a server and has a level, read unless you say otherwise.

  1. Describe the server

    dbwise server add main --host db.example.com --databases app

    The host and the databases the agent may use. The port defaults to 5432 and the SSL mode to require.

  2. Describe the login

    dbwise credential add main-read --user dbwise_read

    A credential holds the database user and where its password lives. It never holds the password.

  3. Type the password

    dbwise set-password main-read

    Run this in a terminal. dbwise is on the PATH of the agent's Bash tool only, so dbwise credential add prints the exact command line to run in a terminal on your system. On Windows use PowerShell or cmd, since Git Bash cannot hide typed input. The command asks with the input hidden and stores the password in the operating system keychain. A password never goes through the chat.

  4. Create the alias

    dbwise alias add main main --level read --credential main-read

    Name the alias, the server, the level and the credential.

  5. Check the setup

    dbwise doctor

    Reconnect the server, then run the doctor. It checks the keychain, the Python environment and every alias, and ends with a verdict line that reads ready when all is well.

The login's database role has to pass the role gate, so a superuser or an owner of tables is refused. The how-to guide has the SQL that creates a role that passes. Create the database roles for dbWise

Raise to diagnose

At diagnose the agent may also run EXPLAIN with ANALYZE, health checks, top queries and index advice. The diagnose level can use a database role of its own, so you can revoke it without touching read.

  1. Create the second role

    A diagnose role is a member of pg_monitor, and a read role should not be: the gate refuses a pg_monitor member on an alias at read. The how-to guide has both recipes.

  2. Add its credential

    dbwise credential add main-monitor --user dbwise_diagnose

    Then type its password with dbwise set-password, as for the first one.

  3. Replace the alias

    dbwise alias add main main --level diagnose --credential read=main-read --credential diagnose=main-monitor

    The alias names one credential for each level up to its own. The same command replaces the alias of that name.

  4. Check it

    dbwise doctor --alias main

    Reconnect the server first. The doctor prints a role check line for each credential and database of the alias, and for the discovery database.
