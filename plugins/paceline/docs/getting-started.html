Getting started with PaceLine

PaceLine has four functions. One is on from the start; the others you turn on when you want them. None of them adds a window: they speak through lines in the conversation.

TL;DRInstall it and context-watch works at once. Run /paceline:pace on to get a budget per hour and advice before every Agent and Workflow launch. pace has no window: it speaks in one line before launches, asks at a hard limit, and answers /paceline:pace status.

Four functions, each on or off by itself

The badge shows the state right after install.

context-watch

On

Warnings before auto-compaction, a snapshot of the session at each compaction, and an optional context gauge on every prompt.

/paceline:context-watch status

pace

Off

A budget per hour against the five-hour and weekly limits, advice before every Agent and Workflow launch, and an unattended night queue.

/paceline:pace on

usage-watch

Off

Reads the account's exact usage, with its model-scoped weekly limits, every 125 seconds while any session is open, so the numbers stay current while sessions are idle. Needs a claude.ai login. The figures are those of the account signed in now, and follow a /login to another account.

/paceline:usage-watch on

cache-watch

Per session

Wakes an idle session just before its one-hour prompt cache expires, so the cache is kept while you are away.

/paceline:cache-watch on

What PaceLine cannot do, and what still works

Set it up in four steps

  1. Install, then start a new session

    /plugin install paceline@agentpit

    context-watch starts working at once. Requires Claude Code 2.1.287 or later and Python 3.9 or later; PitBoard is not needed. If PitBoard is installed, its row shows the limits PaceLine records, from every session. Without PaceLine, PitBoard shows the limits only as its own session saw them.

  2. Turn pace on

    /paceline:pace on

    From now on every Agent and Workflow launch carries a pace line, and a launch at a hard limit asks you first. /paceline:pace off turns it off.

  3. Check the time zone

    /paceline:pace profile set timezone Europe/Kyiv

    pace counts day and night hours in the profile's zone. A new profile takes this machine's zone; set it if the session-start hint says it differs.

  4. Optional: exact usage

    /paceline:usage-watch on

    Without it, numbers come from the last model reply of any session; with it, they come from the same source as /usage.

pace has no window

Where pace shows itself

One working day, in the order pace speaks. Lines addressed to the agent are shown as the agent receives them.

A working day
  1. 08:05Session start: a plan reminder
  2. 09:30Before an Agent launch
  3. 11:00When you ask: /paceline:pace status
  4. 15:40At a hard limit: you are asked
  5. Next day, 07:50After a night: the report

Session start: a plan reminder

While pace is on, a session start reminds the agent of plans that start tomorrow and are not yet confirmed, of a time zone that differs from this machine's, and of a weekly budget likely to go unused.

Pace: unconfirmed plan change(s) start tomorrow — P3 away 2026-10-16 08:00+00:00 .. 2026-10-16 22:00+00:00 ("off on Friday"). Ask the owner once whether the plan still holds, then run `paceline plan confirm <id>`.
How to read it
  • The agent asks you once; paceline plan confirm stops the reminder and changes nothing in the budget.

Before an Agent launch

Before every Agent or Workflow launch the agent receives one line with the advice. It is context for the agent; when pace has no usage data, no line is added.

pace: agents <=2 (active reservations 0) | model opus of opus/sonnet/haiku | 5h 23%/80 | budget 0.86%/h vs norm 1.03
How to read it
  • agents and model: how many parallel subagents pace advises now, and the model out of those allowed.
  • 5h 23%/80: the five-hour window against the threshold above which background work waits.
  • budget vs norm: the weekly percent this hour may spend, against the even rate for this kind of hour.

When you ask: /paceline:pace status

Run /paceline:pace status, or ask the agent for the pace status. The agent runs paceline status in the session's Bash tool, which prints this line, and tells you the budget, the advice and any warning.

paceline status 7d 42% reset 2026-10-18 12:00+00:00 | budget 0.86%/h (weekday norm 1.03) | forecast unused 12% | agents <=2 model opus | 5h 23%/80 | night 5.0% | data 0 min old
How to read it
  • forecast unused: what the week would leave on the table at the recent pace.
  • data 0 min old: how fresh the usage reading is. STALE means older than 30 minutes; the hard limits on the windows are then skipped and the night queue waits.

At a hard limit: you are asked

At a hard limit the launch stops and asks you: by day from 80% of the five-hour window, at night from 95%, or when the weekly limit is used up. While the five-hour window burns toward its threshold, a launch over the advised number of agents asks you too. The reason is put in front of the tool's description, so every prompt surface shows it.

[pace hard limit: 5h window 96% >= 80% background threshold, resets 2026-10-14 18:00+00:00] Explore the payment module pace hard limit: 5h window 96% >= 80% background threshold, resets 2026-10-14 18:00+00:00. Launch Agent anyway? Yes / No
How to read it
  • Yes launches it anyway; No leaves the agent to wait or to work without the subagent.
  • Nothing else is blocked: pace only asks before launches.

After a night: the report

If you leave a night queue running, the agent leaves a morning report from PaceLine's template: done, deferred and why, questions for you, spend against estimates.

## Done - Q3: Update the release notes (agentpit-dev): merged ## Deferred - Q5: Rename the store keys: deferred after 3 attempts, gate failed ## Night budget - Allowance: 5.0% · Surplus: 1.2%
How to read it
  • Every line traces to a queue item, a reservation or a status time stamp.
  • The queue starts only when you start it; nothing runs at night by itself.
