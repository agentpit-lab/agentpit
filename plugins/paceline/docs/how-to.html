PaceLine how-to guides

Task guides for PaceLine. Each guide says when you need it, the steps, and how to tell it worked. Type the /paceline: commands in a session. Run the paceline commands in a session's Bash tool, or ask the agent to run them. The reference lists every option.

Run a night queue

you want the agent to work through a list of tasks while you sleep, within what the week can spare.

  1. Keep the machine awake for the night.

    scripts/night-power.ps1 in the plugin directory turns off sleep on AC power and moves the Windows Update active hours over the night, so a restart does not land mid-queue. Without a switch it is a dry run that prints what it would change. Run it with -Enable before the night and with -Disable after it, in an elevated PowerShell. The previous values are saved in <state>/night-power-state.json. -NightStart and -NightEnd set the hours (default 0 and 8).

    Start the session under caffeinate -i -s, for example caffeinate -i -s claude.

    Start it under systemd-inhibit --what=sleep, for example systemd-inhibit --what=sleep claude.

  2. Turn pace on, if it is off:

    /paceline:pace on

  3. Add the items, each with an estimate in percent of the weekly limit:

    paceline queue add --title "Update the release notes" --repo agentpit-dev --estimate 2
paceline queue add --title "Rename the store keys" --repo agentpit-dev --estimate 3 --depends Q1

    Items get the IDs Q1, Q2, and so on. Add --independent to an item that may run beside other independent items.

  4. Tell the agent to run the queue. It starts the run once:

    paceline auto --start-run

    Then, before each item, it runs paceline auto and follows its exit code:

    • 0 (start): run paceline queue start <id> for the item named in the output, do the work, then paceline queue done <id>. When the item's checks fail, run paceline queue fail <id> and fix them; after gate_fix_attempts (3) failures the item is deferred. When an item needs your permission, run paceline queue defer <id>. Deferring an item also defers the items that depend on it.
    • 10 (wait): wait, then run paceline auto again. With --json, wait_until says until when.
    • 11 (stop): end the run.

  5. In the morning, the agent fills the report template templates/morning-report.md from paceline queue report and the queue's state.

paceline queue report prints the done, deferred, running, and pending items with their estimated and actual spend, for example done 2 (est 5.00% act 4.10%), deferred 1, running 0, pending 0. paceline queue list shows each item's status and, for a deferred item, the reason.

The leftover pool works the same way with --pool (item IDs L1, L2, and so on). Approve it with paceline queue --pool approve; it runs only on the last night before the weekly reset. The explanation says how auto decides.

Declare, move, or cancel a plan

you know a day ahead that you will be away, or that a day will be heavy, and you want the budget to follow.

  1. Declare the plan. Dates are in the profile's time zone, and a bare --to date includes that day:

    paceline plan add --type away --from 2026-10-16 --to 2026-10-16 --phrase "off on Friday"
paceline plan add --type heavy --from tomorrow --to tomorrow --weight 1.5

    An away plan gives its day hours no budget; a heavy plan multiplies their weight by --weight, default heavy_weight (2).

  2. To move or cancel a plan, find it first:

    paceline plan find --text "friday"

    Exit code 0 means one match: use its ID. 3 means several: narrow the search with --on DATE or --type. 4 means none.

  3. Move it, or cancel it:

    paceline plan modify P3 --from 2026-10-17 --to 2026-10-17
paceline plan cancel P3

  4. While pace is on, a session start the day before reminds the agent of a plan that is not confirmed. After you say it still holds, the agent runs paceline plan confirm P3. Confirming stops the reminder and leaves the budget as it is.

add, modify, and cancel end with the new budget, for example plan P3 cancelled; budget 1.21%/h, night 5.0%. paceline plan list shows every plan with its local start and end.

Hold the cache while away

you step away from a session with a long context and want to come back to a warm cache. When a session sits idle for an hour, its one-hour prompt cache expires, and the next turn writes the whole context to the cache again.

  1. In that session, run:

    /paceline:cache-watch on

    It starts only when the session's main thread writes one-hour cache entries. It refuses a session with five-minute entries, or with no cache entry yet, and says why. cache-watch keeps only the main thread's cache: a session whose main thread writes five-minute entries is refused even when its subagents write one-hour entries. The main thread's TTL is Claude Code's setting for the session; subagent TTL settings do not change the decision.

  2. Leave the session idle. After every turn, a Stop hook waits in the background and wakes the session lead minutes (5 by default) before the cache would expire, and no later than 52.5 minutes after the last request. The woken turn keeps the cache for another hour. The agent sends one line, such as Cache kept until 15:30 · wake 1 of 5 · reply stop to stop keeping it, as a push notification and ends the turn without a reply, so the line shows once. The push reaches your phone when the session has Remote Control on and "Push when Claude decides" enabled in /config. Only a session without the push tool gets the line as a reply instead. With a lead up to 7, wakes come every 52.5 minutes; with a larger lead, every 60 - lead minutes.

  3. Any message you send in the session resets the count. After max wakes (5 by default) in a row without a message from you, watching stops. To stop earlier, reply stop or run /paceline:cache-watch off. Ending the session also stops it, and so does a compaction, manual or automatic: the compacted context starts a new cache, so a wake would keep nothing. status then shows off (compacted); run on again to watch the compacted session.

What it cannot do:

  • It keeps only one-hour cache entries. When the main thread switches to five-minute entries, watching stops, one wake tells you so, and status shows off (five-minute cache). See one-hour entries only and the self-stop.
  • It keeps only the main thread's cache. A finished subagent that you resume after its cache expired starts cold. See main thread only.
  • It refuses a session with no cache entry yet. See a cache entry first.
  • A computer that sleeps past the cache's expiry misses the wake and loses the cache. cache-watch then turns off, status shows off (cache expired before the wake), and your next message brings a one-line notice. See sleep.
  • It keeps no cache in claude -p runs. See non-interactive runs.
  • Without Remote Control and "Push when Claude decides", no push reaches your phone. See the push.
  • In a terminal session whose context is at or above the idle compaction threshold, Claude Code is expected to compact the conversation about 54 minutes after the last request (Claude Code, settings reference, read 2026-10-15). cache-watch wakes the session no later than 52.5 minutes after the last request, so the wake comes before idle compaction, and as a new request it restarts Claude Code's idle count. When the wakes run out, cache-watch turns itself off and Claude Code can compact about 54 minutes after the last wake. See idle compaction after the last wake.

A wake keeps the cache for far less than losing it costs. The woken turn reads the context from the cache; the first turn after the cache's expiry writes the whole context to the cache again, which by Anthropic's API prices costs at least 20 times the read (a one-hour cache write is 2 times the input price, a cache read 0.1 times or less). Each wake still counts against the five-hour limit; how much a cache read weighs in subscription limits is not published. With the defaults, that is at most five wakes per absence; see each wake counts against the five-hour limit. To change the defaults, run /paceline:cache-watch config --lead 10 --max 3; to change them for one session, pass the same options to on.

/paceline:cache-watch status shows the session as on, with the cache expiry and the next wake, for example <session id> · on · lead 5 min · wakes 0/5 · cache 1h · expires 15:30 · next wake 15:22.

Recover after a compaction

a session was compacted, and you or the agent need what the summary dropped. context-watch is on from install, so this works without setup.

  1. Before the compaction, context-watch puts a line such as context: 612k / 967k auto-compact point (63%) on every prompt. When the context first passes 85% and then 95% of the auto-compaction point, the agent is told once per level to write its recovery point to the task's status file. The levels reset after each compaction.

  2. At each compaction of the main conversation, automatic or /compact, PaceLine writes .claude/paceline/<session id>.md in the project. It holds your last 3 prompts, the agent's last 2 replies, the last 5 tool calls with their inputs cut to 200 characters (without results), and every file the agent wrote or edited in the session.

  3. The summary is told to keep the snapshot path. Right after the compaction, the agent is told to read the snapshot and the task's status files before its next step.

  4. To read a snapshot yourself, open the file. /paceline:context-watch status prints the project's snapshot folder.

context-watch never vetoes, delays, or starts a compaction, and leaves subagent compactions alone. An error in context-watch leaves the turn as it was. With auto-compaction off, the line measures against the context window, and no warnings come. Snapshots older than 14 days are removed when a session starts in the project.

To change it, run /paceline:context-watch config, for example --levels 80,90 for earlier warnings, --line off to hide only the line, or --days 30 to keep snapshots longer.

after a compaction, /paceline:context-watch status counts the snapshot, for example snapshots: /home/me/project/.claude/paceline (1 file), and the agent's next step starts by reading it.

Keep usage current while idle

you want pace and status line plugins to show the exact figures /usage shows, including the model-scoped weekly limits, while no session makes requests.

Before you turn it on: usage-watch is off until you run /paceline:usage-watch on. It reads https://api.anthropic.com/api/oauth/usage, an endpoint outside Anthropic's published API reference, through Claude Code with the session's own login; its address, answer format, or availability can change without notice. It needs a claude.ai login and an open session with PaceLine, pauses while the computer sleeps, and sends nothing while CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC is set. When the endpoint fails, /paceline:usage-watch status shows last error: HTTP <status> or unexpected response, PitBoard's model-scoped limits disappear after 15 minutes, and pace's model-scoped rules stop applying. Without usage-watch, the limits writer, the five-hour and weekly readings from each session's turns, pace's budget, and the night queue keep working, with data as of the last turn. The limitations list each case: the login, off by default, the endpoint, an open session, sleep, and the traffic setting.

  1. Turn usage-watch on:

    /paceline:usage-watch on

    The switch holds for every session of the same Claude Code configuration directory and takes effect within 10 seconds.

  2. Keep at least one session with PaceLine open, busy or idle. usage-watch reads the account's usage every 125 seconds while a session is open. It needs a claude.ai login.

  3. To let pace account for a model's own weekly limit, pass the model with --model, or set PACELINE_MODEL.

/paceline:usage-watch status shows a recent last success and last error: none. /paceline:pace status shows a data age of a few minutes at most, and lists the model-scoped buckets after the weekly figure, for example 7d 34% (Fable 7%). If nothing shows, see usage-watch shows nothing.

Use two accounts on one machine

you sign in to more than one Claude account on this computer and want pace to show the limits of the account you use now.

Which setup: use one configuration directory and /login when you use one account at a time. The same holds when Claude Code Desktop is on one account and a terminal on the other: a Desktop session takes its account from the variables its host passes, so each session shows its own figures. In a plain terminal, paceline status ends with other account <8 digits> active; --account <8 digits> while the other account has a fresh reading, and paceline status --account <8 digits> shows its figures. PaceLine keeps each account's readings in a partition of its own, and pace reads the partition of the account signed in now. Use a configuration directory per account (CLAUDE_CONFIG_DIR) when two terminal sessions on different accounts run at the same time, or when each needs its own profile, plans, and night queue. See Each configuration directory keeps its own state.

  1. Update with /plugin marketplace update agentpit and restart every open session. A session still on PaceLine 0.2.5 does not tag its readings and mixes the accounts until it restarts.

  2. Do not run /login during a night run. The run stops with account changed during the run.

  3. Run /login and sign in to the other account.

  4. Run /paceline:pace status. It shows the new account's figures at once when that account has a partition from an earlier session. Otherwise it stops with no usage data yet for the signed-in account until the first reply in a session signed in to that account, or until the next usage-watch reading, which comes at most 125 seconds after the last one.

status does not end with account unknown, and paceline status --json shows data.account.state as known. A /login back to the first account shows its last figures at once.

What the messages mean:

  • no usage data yet for the signed-in account: the signed-in account has no readings yet. It fills after the first reply in a session with PaceLine loaded.
  • account unknown (<reason>): PaceLine cannot tell that the figures belong to the signed-in account. The reason is untagged, no-file, unreadable, or no-account. See Status says account unknown.
  • After an update from 0.2.5, the figures show account unknown (untagged) until the account's first tagged reading arrives.

Change a profile setting

the budget counts in the wrong time zone, your working day is longer or shorter than 08:00 to 22:00, or a limit in the profile does not fit your machine.

  1. Look at the current values:

    paceline profile

  2. Change one key. The value is read as JSON when it parses, else as text:

    paceline profile set timezone America/New_York
paceline profile set day_hours '[8, 24]'
paceline profile set min_free_commit_mb 1024

    Set these first: timezone, day_hours, night_hours, models, and the memory floor (min_free_commit_mb and commit_reserve_mb). The defaults for the memory floor and the hours are starting points. If a confirmation prompt appears at most Agent launches, lower min_free_commit_mb; if your day is longer, widen day_hours.

  3. To keep UTC while this machine is in another zone, run paceline profile set timezone UTC. That also silences the time zone hint at session start.

profile set prints KEY: OLD -> NEW and the new paceline status line, for example day_hours: [8, 22] -> [8, 24]. A refused value exits 2, prints the reason, and changes nothing. The profile keys list what each key does and its range.
