Усунення проблем PaceLine

Знайти симптом, потім прочитати його причину, команду для перевірки і виправлення. Команди paceline запускають у Bash tool сесії або доручають агентові.

paceline doctor перевіряє середовище виконання Python, каталог стану, перемикач pace, inbox, файл лімітів, поточний акаунт, пошук процесів, показник пам'яті, часовий пояс, hooks і журнал налагодження та виводить підказку щодо знайденого. Для більшості проблем спершу запустити її.

Pace виглядає неактивним

Перед запуском Agent або Workflow не з'являється рядок pace:, і жоден запуск не просить підтвердження.

Одне з такого:

  • pace вимкнено. Після встановлення він вимкнений, доки його не ввімкнути.
  • pace ще не має даних про використання. Файл лімітів заповнюється після першої відповіді в сесії із завантаженим PaceLine. Доти paceline status завершується помилкою, а hook нічого не додає.
  • Hooks не можуть запустити Python. Див. Hook повідомляє про проблему з Python.
  • PACELINE_STATE_DIR задано в shell, але не там, де запускається Claude Code, тож hooks і команди користуються різними каталогами стану.
paceline status
paceline doctor

paceline status закінчується на pace hooks off (paceline on), поки pace вимкнено, і завершується помилкою paceline: no usage data yet до першого показника. У paceline doctor перевірка switch показує перемикач, а перевірка paths — каталог стану.

Запустити paceline on. Якщо даних немає, зробити один хід у будь-якій сесії і знову запустити paceline status. Задати PACELINE_STATE_DIR там, де запускається Claude Code, або ніде.

Бюджет виглядає неправильним

Бюджет на годину значно вищий або нижчий за очікуваний або дорівнює 0.

Бюджет залежить від профілю і планів. Звичайні причини:

  • Часовий пояс або денні години профілю не збігаються з реальним днем, тож годинник потрапляє на нічну або неробочу годину, і показано бюджет наступної денної години.
  • Оголошений план away не дає бюджету денним годинам свого дня; план heavy збільшує їхню частку.
  • Резерв утримує reserve_pct до кінця тижня.
  • У вихідні денні години вихідних разом отримують щонайбільше weekend_cap_pct тижня.
  • Коли задано --model, PACELINE_MODEL або ANTHROPIC_MODEL, тижневий bucket окремої моделі враховується, якщо він вищий за тижневий показник.
  • Жодна година не може отримати більше за five_hour_to_week_pct / 5 відсотка тижня.
paceline status --json
paceline plan list

У JSON now_local — годинник у поясі профілю, in_day_hours каже, чи це денна година, current_plan — чинний план, reserve_pct і spendable_pct показують резерв, weekend показує межу вихідних, а weekly.matched_scoped називає bucket окремої моделі, який враховується.

Виправити профіль командою paceline profile set (див. Зміна параметра профілю) або скасувати план, який уже не актуальний. Симулятор бюджету показує, як кожне вхідне значення змінює бюджет, а в поясненні наведено правила.

Дані STALE

paceline status показує STALE data N min old, а рядок pace: показує STALE data.

Найновіший показник старший за stale_threshold_min (30 хвилин). Без usage-watch показники оновлюються лише тоді, коли сесія на цій машині робить хід моделі, тож дані старіють, поки жодна сесія не працює. Поки дані застарілі, жорсткі ліміти п'ятигодинного і тижневого вікон не застосовуються, і нічна черга чекає.

paceline merge --verbose
paceline doctor

paceline merge --verbose одразу зливає inbox і виводить час найновішого показника. У paceline doctor перевірка inbox показує вік найновішого показника, а перевірка limits — вік кожного bucket і позначає показник із майбутнього.

Зробити хід у будь-якій сесії або ввімкнути usage-watch, щоб показники оновлювалися, поки сесії простоюють (див. Актуальне використання під час простою).

Неправильний часовий пояс

Денні й нічні години зсунуті, або старт сесії повідомляє, що профіль рахує в UTC, хоча ця машина в іншому поясі.

Новий профіль бере пояс цієї машини, лише коли може його визначити і Python тут має для нього дані; інакше профіль лишається в UTC. Пояс береться з TZ, якщо там назва поясу, далі на Windows з ICU (Windows 10 1903 і новіші), а на macOS і Linux із цілі /etc/localtime або з /etc/timezone. Наявний профіль зберігає свій пояс.

Без пакета tzdata Python може не мати даних про часові пояси, що часто трапляється на Windows. Тоді PaceLine знає лише UTC і вбудовані пояси Центральної та Східної Європи з літнім часом ЄС: Europe/Madrid, Europe/Paris, Europe/Berlin, Europe/Rome, Europe/Amsterdam, Europe/Brussels, Europe/Vienna, Europe/Warsaw, Europe/Prague, Europe/Stockholm, Europe/Kyiv, Europe/Kiev, Europe/Helsinki, Europe/Athens і Europe/Riga.

paceline profile check

Команда виводить пояс профілю, чи його підтверджено, і визначений пояс або підказку з командою, яку слід запустити.

Задати пояс:

paceline profile set timezone America/New_York

Якщо команда відхиляє пояс, бо Python не має для нього даних, спершу встановити дані командою python -m pip install tzdata. Щоб лишити UTC, запустити paceline profile set timezone UTC; це також зупиняє підказку.

Hook повідомляє про проблему з Python

Claude Code показує помилку hook, у якій згадано python3 або python, або функція мовчить, хоча її ввімкнено.

Кожна команда hook запускає python3, якщо він працює, інакше python. Коли жодного немає в PATH, hook завершується помилкою. Коли знайдений Python має версію, нижчу за 3.9, hooks нічого не роблять і записують рядок hook.python у <state>/debug.log. На Windows python, який лише відкриває Microsoft Store, вважається відсутнім.

paceline doctor

Перевірка runtime показує версію Python і які з python3 та python є в PATH. На Python версії, нижчої за 3.9, paceline одразу зупиняється з повідомленням, що називає версію. Рядки з "failure":true у <state>/debug.log фіксують, що пропустив hook; hook записує їх навіть без прапорця налагодження.

Встановити Python 3.9 або новіший і додати його в PATH як python3 або python, потім почати нову сесію.

Нічна черга чекає всю ніч

paceline auto раз у раз завершується з кодом 10 (wait), і жоден елемент не стартує.

auto чекає, коли виконується одна з умов:

  • Дані про використання застарілі. Якщо агент лише чекає між викликами, жодна сесія не робить ходу, і без usage-watch дані не оновлюються.
  • П'ятигодинне використання на нічному порозі (95%) або на жорсткій зупинці.
  • За темпу витрати п'ятигодинне вікно досягло б нічного порога (95%) до скидання, а ліміт агентів дорівнює 0. Тоді reasons містить причину перевитрати, наприклад 5h burn 42.7%/h vs budget 13.9%/h: 95% at <time>, before reset <time>.
  • Якийсь елемент досі в стані running, або залежності наступного елемента не виконано. Елемент, який запустили і так і не позначили виконаним, тримає чергу в очікуванні.
  • Жодна дозволена модель не має тижневого запасу для елемента.
  • Даних про використання немає взагалі.
paceline auto --json
paceline queue list

reasons у JSON називає причину, а wait_until встановлено, доки п'ятигодинне вікно заповнене або витрачається занадто швидко. paceline queue list показує елементи, що застрягли в running.

Для застарілих даних увімкнути usage-watch перед ніччю. Для елемента, що застряг у running, запустити paceline queue done <id>, paceline queue fail <id> або paceline queue defer <id>. Для заповненого п'ятигодинного вікна черга продовжиться після wait_until. Для перевитрати пізніше знову запустити paceline auto: черга стартує, щойно темп знизиться. Якщо жодна модель не має запасу, додати модель до routine_models або models чи знизити оцінку елемента, якщо її завищено.

Статус каже account unknown

paceline status закінчується на account unknown (<reason>), рядок pace: перед запуском показує account unknown, а картки PitBoard 5h limit і Week мають рядок Account зі значенням unknown.

PaceLine не може визначити, що показники належать акаунту, у який увійдено. Причину вказує код:

  • untagged: у rate-limits.json немає розділу поточного акаунта, і показники взято з розділу unknown, де лежать показники без поля account. Так виглядає файл, записаний до появи акаунтів, і показники програм, що їх не позначають.
  • no-file: файл .claude.json Claude Code відсутній, тож PaceLine не може назвати акаунт.
  • unreadable: .claude.json не розбирається або його не вдалося прочитати двічі поспіль.
  • no-account: у .claude.json немає oauthAccount.accountUuid, наприклад коли не увійдено в жоден акаунт.

За кодами no-file, unreadable або no-account PaceLine читає верхній рівень файлу лімітів, який копіює найновіший розділ. Нічна черга чекає з account unknown, доки прогін, що триває, не може назвати свій акаунт.

paceline doctor
paceline status --json

Перевірка account у paceline doctor дає стан і код причини, але не сам акаунт. data.account у status --json має той самий стан і причину, а також ключ акаунта.

Для untagged достатньо одного ходу в сесії з завантаженим PaceLine: її показник несе акаунт і починає розділ акаунта, після чого позначка зникає. Для no-file, unreadable і no-account увійти в Claude Code; якщо задано CLAUDE_CONFIG_DIR, файлом є <CLAUDE_CONFIG_DIR>/.claude.json, інакше ~/.claude.json. Не копіювати файл і не редагувати його вручну.

usage-watch нічого не показує

paceline status не показує buckets окремих моделей, і дані старіють, поки сесії простоюють, хоча usage-watch увімкнено.

usage-watch потребує входу через claude.ai і відкритої сесії з PaceLine. Без входу через claude.ai він нічого не надсилає. Поки задано CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC, Claude Code відхиляє запит, і usage-watch повторює його через 10 хвилин. Коли endpoint використання відповідає помилкою або у форматі, який PaceLine не читає, файл лімітів зберігає показники сесій.

paceline usage-watch status
  • last attempt: never з увімкненим перемикачем: жодна сесія не відкрита, або Claude Code не дає входу для запиту.
  • last error: network error: запит відхилено або він не дійшов до сервера, наприклад через CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC.
  • last error: HTTP <status> або unexpected response: endpoint відповів помилкою або у форматі, який PaceLine не читає.

Тримати сесію відкритою, увійти в Claude Code з акаунтом claude.ai або прибрати CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC. Після відповіді HTTP 429 usage-watch повторює спробу через 125 секунд; після будь-якої іншої помилки — через 10 хвилин.

Діагностика для звіту про помилку

Коли проблему не пояснює жоден інший розділ цієї сторінки, записати трасування і зібрати архів:

  1. Створити файл-прапорець <state>/debug.on.
  2. Якийсь час працювати з Claude Code як зазвичай.
  3. Запустити paceline doctor --live --bundle ~/paceline-doctor.zip.
  4. Видалити файл-прапорець.

Поки існує цей прапорець, PaceLine і його hooks дописують до <state>/debug.log по одному рядку JSON на кожен крок. PACELINE_DEBUG=1 так само трасує одну команду. Журнал і архів записують домашній каталог як ~. Архів містить введені фрази планів, мітки резервувань і ID сесій, тож перед передачею його слід переглянути.
