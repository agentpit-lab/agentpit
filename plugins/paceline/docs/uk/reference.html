Довідник PaceLine

Команди, коди виходу, ключі профілю, змінні середовища, файли і формати, які читають і записують інші програми. Таблиці беруться з коду плагіна: python .ci/docs_facts.py build записує його факти, а python .ci/pages.py build будує з них таблиці. Примітки під кожною таблицею написано вручну.

На цій сторінці <state> — каталог стану: $PACELINE_STATE_DIR, інакше <config>/state/paceline, де <config> — це $CLAUDE_CONFIG_DIR, інакше ~/.claude.

Спільні параметри

Усі команди, крім cache-watch, context-watch і usage-watch, приймають такі параметри:

  • --json: вивести повний результат як JSON.
  • --model ID: ID поточної моделі. Вибирає тижневий bucket окремої моделі, якщо такий є у файлі лімітів. Типово: $PACELINE_MODEL, інакше $ANTHROPIC_MODEL.
  • --session ID: ID сесії Claude Code. Типово: $CLAUDE_SESSION_ID.
  • --no-merge: використати файл лімітів як є, без попереднього злиття inbox.
  • --now TIME: час ISO 8601, який використовується як годинник, для сценаріїв «а що, якщо» і тестів. Типово: $PACELINE_NOW, інакше реальний час.
  • --state-dir DIR: каталог стану для цієї команди.

Стан і перемикачі

  • paceline status виводить один рядок, наприклад:

    7d 34% reset 2026-10-03 03:00+00:00 | budget 1.45%/h (weekday norm 1.03) | agents <=3 model opus | 5h 23%/80 | night 15.2% | data 1 min old

    Поля по порядку: тижневе використання з buckets окремих моделей, якщо вони є, і місцевий час скидання; бюджет на годину відносно норми для такого самого типу години (ставку буднього дня додано, коли вона відрізняється від бюджету); forecast unused, коли історії достатньо; рекомендована кількість паралельних агентів і модель; п'ятигодинне використання відносно поточного порогу; нічна квота; вік даних, із STALE попереду, коли дані старші за stale_threshold_min. Інші поля з'являються лише тоді, коли застосовні: account unknown (<reason>), коли не вдається встановити, що показники належать поточному акаунту (причини: untagged, no-file, unreadable і no-account), host memory unknown, pace hooks off (paceline on), WARNING про те, що решта тижня близька до місткості денних годин, причини блокування, паузи або обмеження моделей, непідтверджені плани, що починаються завтра, і пропозиція пулу залишкових задач. Як обчислюється кожне число, описано в поясненні. З --json поле data.account має вигляд {"state": "known" | "unknown", "key": <ключ поточного акаунта або null>, "reason": <код або null>}; key — односторонній ключ з inbox, за яким ідентифікатор акаунта не відновити.

  • paceline auto [--start-run] виводить параметри для наступного елемента нічної черги, наприклад auto: START Q3 | budget 4.20% | agents <=3 models opus,sonnet,haiku, і завершується з кодом 0 (start), 10 (wait) або 11 (stop). --start-run починає прогін цієї ночі: фіксує нічну квоту і тижневе використання, від якого вона рахується. Повторний запуск тієї ж ночі зберігає цей прогін. З --json результат містить action, next_item, budget_for_next_item_pct, max_parallel_agents, max_heavy_runs, allowed_models, wait_until і reasons. Прогін пам'ятає акаунт, під яким стартував. Коли увійдено в інший акаунт, auto зупиняється з причиною account changed during the run, яку auto перевіряє перед усіма іншими умовами зупинки; коли акаунт не визначено, auto очікує з причиною account unknown.
  • paceline on і paceline off записують перемикач pace, <state>/pace.json.
  • paceline calibrate читає історію лімітів і завершені резервування та пропонує нові значення для five_hour_to_week_pct, reserve_pct, weekend_cap_pct, night_base_pct і subagent_estimate_pct, а також співвідношення фактичної вартості до оціненої для оцінок задач. Команді потрібно calibration_min_days днів історії, і вона нічого не змінює.
  • paceline profile виводить профіль; show — типова дія. paceline profile set KEY VALUE змінює один ключ із перевірками (див. Ключі профілю). paceline profile check порівнює часовий пояс профілю з поясом цієї машини і виводить підказку, коли вони різняться.
  • paceline merge [--verbose] одразу зливає inbox у файл лімітів. Без --verbose або --json команда нічого не виводить.
  • paceline doctor [--live] [--bundle PATH] діагностує PaceLine на цій машині. Команда виконує такі перевірки: runtime, paths, switch, inbox, limits, account, process, memory, timezone, hooks і debug_log; кожна дає ok, warn або fail, деякі з підказкою. Перевірка account повідомляє known або unknown і код причини (no-file, unreadable, no-account), і нічого з .claude.json. --json показує докази кожної перевірки. Без --live команда нічого не змінює; --live також виконує одне злиття. --bundle записує zip-архів зі звітом, журналом налагодження, профілем, перемикачем pace, файлом лімітів, останніми 50 рядками історії та останніми 20 резервуваннями. Звіт і архів записують домашній каталог як ~. Архів містить введені фрази планів, мітки резервувань і ID сесій.

Плани

  • paceline plan add --type away|heavy --from DATE --to DATE [--weight W] [--phrase TEXT] оголошує майбутню відсутність (away) або напружений день (heavy). Дата — це YYYY-MM-DD, today, tomorrow або дата й час ISO 8601, у часовому поясі профілю. Дата --to без часу включає весь день. Вага типово 0 для away і heavy_weight для heavy. --phrase зберігає власні слова автора плану, щоб пізніший find --text міг їх знайти. ID планів — P1, P2 і так далі.
  • paceline plan list виводить усі оголошені плани.
  • paceline plan find [--text TEXT] [--on DATE] [--type away|heavy] виводить плани, фраза яких містить текст, які перетинають цей день або мають цей тип. Команда завершується з кодом 0 для одного збігу, 3 для кількох і 4 для жодного.
  • paceline plan modify ID [--from DATE] [--to DATE] [--weight W] [--phrase TEXT] змінює план і знімає його підтвердження.
  • paceline plan cancel ID видаляє план.
  • paceline plan confirm ID позначає план підтвердженим сьогодні. Після цього нагадування на старті сесії для нього припиняються. Бюджет не змінюється.
  • paceline plan tomorrow виводить плани, що починаються завтра і сьогодні не підтверджені.

add, modify і cancel закінчують свій рядок новим бюджетом, наприклад plan P4 away 2026-10-16 00:00+02:00 .. 2026-10-17 00:00+02:00 added; budget 1.21%/h, night 5.0%. Плани, що закінчилися, видаляє наступна команда.

Резервування

  • paceline reserve acquire --kind subagent|workflow|gate|queue [--estimate PCT] [--label TEXT] [--key KEY] [--pid PID] [--item ID] утримує резервування. --estimate — очікувана вартість у відсотках тижневого ліміту; параметр обов'язковий для всіх видів, крім subagent, для якого типово береться subagent_estimate_pct. З --key сесія утримує одне резервування на ключ, а повторний acquire його поновлює. --pid — процес Claude Code, якому належить резервування; типово це найближчий батьківський процес, назва якого починається з claude. ID резервувань — R- і вісім шістнадцяткових цифр.
  • paceline reserve renew ID поновлює lease. Команда завершується з кодом 4, коли резервування закінчилося або його звільнено.
  • paceline reserve release [ID] [--key KEY] [--actual PCT] звільняє одне резервування, назване за ID або за ключем. Фактична вартість типово дорівнює зміні тижневого використання від моменту отримання резервування. Команда завершується з кодом 4, коли звільняти нічого.
  • paceline reserve release-session [--target-session ID] звільняє всі резервування сесії, типово тієї, що вказана в --session.
  • paceline reserve prune відкидає резервування, lease яких закінчився або процес яких зник.
  • paceline reserve list виводить активні резервування.
  • paceline reserve reconcile підсумовує завершені резервування за видами: кількість, суми оцінок і фактичних витрат і медіану співвідношення фактичної вартості до оцінки.

Резервування відкидається, коли закінчується його lease (lease_ttl_min без ключа, agent_lease_ttl_min із ключем) або коли зникає його процес. Завершене резервування отримує позначку overlapped, якщо одночасно з ним виконувалося інше: його виміряна вартість — це зміна тижневого використання всього акаунта, тож паралельна робота її завищує.

Нічна черга і пул залишкових задач

Кожна команда paceline queue працює з нічною чергою, а з --pool — з пулом залишкових задач. ID елементів черги — Q1, Q2 і так далі; ID елементів пулу — L1, L2 і так далі. Елемент перебуває в стані pending, running, done або deferred.

  • add --title TEXT --repo NAME --estimate PCT [--independent] [--depends ID,ID] додає елемент. --independent дозволяє йому виконуватися поруч з іншими незалежними елементами. Кожна залежність уже має існувати.
  • list виводить елементи. report підсумовує поточний прогін: виконані, відкладені, активні й очікувані елементи із сумами їхніх оцінок і фактичних витрат.
  • approve (лише для пулу) схвалює пул для поточного тижневого вікна.
  • start ID [--pid PID] позначає очікуваний елемент як running і утримує для нього резервування виду queue.
  • done ID [--actual PCT] позначає його як done; фактична вартість типово дорівнює зміні тижневого використання від старту.
  • fail ID [--reason TEXT] рахує одне невдале виправлення перевірок елемента. Після gate_fix_attempts невдач елемент відкладається.
  • defer ID [--reason TEXT] відкладає елемент; типова причина — needs owner permission.
  • retry ID повертає елемент у pending і скидає лічильник невдач.
  • remove ID видаляє елемент. Команда відхиляється, поки від елемента залежить очікуваний або активний елемент.
  • clear-done видаляє елементи в стані done.

Відкладення елемента, через defer або через останній fail, відкладає також кожен очікуваний чи активний елемент, що від нього залежить.

cache-watch

  • paceline cache-watch on --session ID --data-dir DIR [--lead MIN] [--max N] спостерігає за однією сесією. Команда завершується з кодом 3 і виводить not started із причиною, коли не знаходить транскрипту сесії, ще не має годинного запису кешу або знаходить п'ятихвилинні записи кешу. cache-watch утримує лише годинний кеш промпту; коли під час спостереження основний потік переходить на п'ятихвилинні записи, він зупиняється сам, а status показує сесію як off (five-minute cache). Після рядка сесії команда on виводить два рядки про вартість пробудження: розмір контексту і те, що повторний запис контексту після закінчення терміну кешу коштує щонайменше в 20 разів більше за читання з кешу під час пробудження. Див. обмеження.
  • paceline cache-watch off --session ID --data-dir DIR припиняє спостереження за сесією.
  • paceline cache-watch status --data-dir DIR виводить усі сесії під спостереженням: увімкнено чи вимкнено і чому (operator, five-minute cache, no reply after N wakes, compacted, cache expired before the wake), кількість пробуджень, час закінчення терміну кешу і наступне пробудження. Команда видаляє стан сесій, транскрипт яких не змінювався 24 години.
  • paceline cache-watch config --data-dir DIR [--lead MIN] [--max N] показує або змінює типові значення: lead — 5 хвилин (від 1 до 30), max — 5 пробуджень (від 1 до 20). --lead і --max у команді on діють лише для цієї сесії.

Каталог даних — це ${CLAUDE_PLUGIN_DATA} плагіна. Skill /paceline:cache-watch сам підставляє ID сесії та каталог даних.

context-watch

  • paceline context-watch status [--project DIR] виводить налаштування, теку знімків проєкту з кількістю знімків і файл налаштувань.
  • paceline context-watch config [--on|--off] [--line on|off] [--levels 85,95] [--days N] показує або змінює налаштування. --off вимикає рядок, попередження і знімки. --line off ховає лише рядок. Рівні — цілі відсотки від 50 до 99 за зростанням. Знімки зберігаються від 1 до 90 днів. Зміни діють з наступного промпту.

Типово: увімкнено, рядок увімкнено, попередження на 85% і 95%, знімки зберігаються 14 днів.

usage-watch

  • paceline usage-watch on і paceline usage-watch off записують перемикач, <state>/usage-watch.json.
  • paceline usage-watch status виводить перемикач, останню спробу, останній успіх і останню помилку. Час подано в ISO 8601 в UTC або як never.

Профіль — це <state>/pace-profile.json. Його створює перша команда paceline. Новий профіль бере часовий пояс цієї машини, якщо Python може використати цей пояс тут, і записує його як підтверджений; інакше лишається UTC. Ключі, яких бракує у файлі, під час читання заповнюються типовими значеннями. version, plans, next_plan_id і timezone_confirmed веде сам PaceLine, і в таблицю не входять.

paceline profile set KEY VALUE читає VALUE як JSON, якщо воно розбирається, інакше як текст. Значення має відповідати типу і діапазону ключа: відсотки від 0 до 100, кількості й розміри не від'ємні, години у форматі [start, end] з 0 <= start < end <= 24, reserve_decay_start як день тижня від 0 до 6 і година від 0 до 23, непорожні списки моделей і часовий пояс, який Python може тут використати. Відхилене значення завершується з кодом 2 і причиною в stderr. У разі успіху команда виводить KEY: OLD -> NEW і рядок paceline status. Задання timezone також встановлює timezone_confirmed у true. Файл досі можна редагувати вручну; на ручне редагування перевірки не поширюються.

Що робить кожен ключ:

  • timezone: пояс IANA, який використовують усі правила за настінним годинником, наприклад America/New_York.
  • day_hours: денні години, початок включно, кінець не включно. Бюджет отримують лише денні години.
  • night_hours: нічні години, коли працює нічна черга. Година поза обома проміжками — неробоча і бюджету не отримує.
  • weekday_weight, weekend_weight: відносна вага денної години буднього і вихідного дня.
  • weekend_cap_pct: найбільша частка тижня у відсотках, яку денні години вихідних можуть витратити разом.
  • reserve_pct: частка тижня, яка утримується, доки резерв не почне зменшуватися.
  • reserve_decay_start: коли резерв починає зменшуватися, як {"weekday": W, "hour": H} за місцевим часом; понеділок — 0. Типово п'ятниця, 18:00.
  • five_hour_threshold_day, five_hour_threshold_night: п'ятигодинне використання у відсотках, на якому фонова робота стає на паузу, а запуск Agent або Workflow спершу просить підтвердження.
  • five_hour_hard_stop: п'ятигодинне використання, на якому рекомендація не запускає нічого нового.
  • five_hour_to_week_pct: частка тижня, яку коштує одне повне п'ятигодинне вікно. Визначає максимум для будь-якої години: це значення, поділене на 5, у відсотках тижня на годину. paceline calibrate пропонує виміряне значення.
  • heavy_weight: типова вага плану heavy.
  • night_base_pct: нічна квота до додавання будь-якого надлишку.
  • host_night_capacity_pct: необов'язкова межа нічної квоти; null означає, що межі немає.
  • lease_ttl_min, agent_lease_ttl_min: lease резервування без ключа і з ключем, у хвилинах.
  • subagent_estimate_pct: оцінена вартість одного субагента у відсотках тижня.
  • stale_threshold_min: дані, старші за цю кількість хвилин, вважаються застарілими.
  • usage_snapshot_max_age_sec: команда, яка бачить дані, старші за цю кількість секунд, спершу зливає inbox.
  • capacity_warn_ratio: paceline status попереджає, коли залишок тижня досягає цієї частки від того, що можуть витратити денні години, які лишилися.
  • auto_refresh_five_hour_pct, auto_refresh_cache_sec: на цьому п'ятигодинному використанні або вище auto спершу зливає inbox, якщо дані старші за цю кількість секунд.
  • min_free_commit_mb: вільна пам'ять у MiB, нижче якої нова робота не запускається.
  • commit_reserve_mb, heavy_job_mb, max_heavy_runs: дозволена кількість важких запусків — min(max_heavy_runs, (free memory - commit_reserve_mb) // heavy_job_mb), але не менше 0.
  • max_agents: найбільша кількість паралельних агентів, яку рекомендує pace.
  • models: родини моделей у порядку переваги.
  • routine_models: моделі для рутинної роботи, поки рекомендація обмежує моделі.
  • throttle_weekly_pct: тижневе використання, з якого рекомендація обмежує моделі, поки до скидання лишається понад 24 години.
  • scoped_exhausted_pct: тижневий bucket окремої моделі на цьому рівні вилучає її модель із дозволених. Buckets окремих моделей надходять лише від usage-watch.
  • leftover_suggest_pct: прогнозована невикористана частка, вище якої pace пропонує пул залишкових задач.
  • gate_fix_attempts: кількість невдалих виправлень, після якої елемент черги відкладається.
  • calibration_min_days: кількість днів історії, потрібна для paceline calibrate.

Файл лімітів: формат для читання

<state>/rate-limits.json містить найновіші показники лімітів з усіх сесій на цій машині. Його може читати плагін status line або будь-яка інша програма. Формат:

{
  "observed_at": "2026-10-11T09:30:00.000Z",
  "source": "payload",
  "session_id": "<session that gave the newest reading>",
  "model": "<its model id or null>",
  "five_hour": {"used_percentage": 42.5, "resets_at": "2026-10-11T12:00:00.000Z",
                "observed_at": "2026-10-11T09:30:00.000Z", "source": "payload"},
  "seven_day": {"used_percentage": 18, "resets_at": "2026-10-16T03:00:00.000Z",
                "observed_at": "2026-10-11T09:28:00.000Z", "source": "payload"},
  "account": "069e3589b134b882",
  "accounts": {
    "069e3589b134b882": {"observed_at": "2026-10-11T09:30:00.000Z", "source": "payload", "...": "..."},
    "9f44059c413565ef": {"observed_at": "2026-10-10T18:02:00.000Z", "source": "payload", "...": "..."}
  }
}

Поля над account — це найновіший розділ, скопійований на верхній рівень. Програма, що читає файл і про акаунти нічого не знає, читає їх як раніше.

  • observed_at — час найновішого bucket; кожен bucket має власний. Час подано в ISO 8601 в UTC.
  • resets_at округлено до хвилини, і він може бути null.
  • Будь-якого bucket може не бути. Невідомі поля ігнорувати.
  • source у bucket — це payload (показник сесії) або usage-endpoint (точний показник використання акаунта). source верхнього рівня — це source найновішого bucket.
  • scoped, якщо є, — список тижневих buckets окремих моделей у формі {"name", "used_percentage", "resets_at"?}. Він надходить лише з точним тижневим показником і заміняється наступним. Він відкидається, коли seven_day переходить в інше вікно без нього.
  • Файл заміняється через тимчасовий файл і перейменування, тож читання ніколи не бачить частково записаного файлу. Файл записується лише тоді, коли змінюється.
  • accounts зіставляє ключ акаунта із записом цього акаунта у форматі вище, без account і accounts. Ключ — 16 шістнадцяткових цифр у нижньому регістрі, або unknown для показників без акаунта. Кожен розділ зливається окремо. Програма, що читає файл і знає акаунт, який обслуговує, читає accounts[<its key>], інакше accounts["unknown"] і каже, що акаунт невідомий. Чужого розділу вона ніколи не читає.
  • account — це ключ розділу, скопійованого на верхній рівень, або null, коли цей розділ unknown.
  • Розділ, який жоден показник не оновлював 7 днів, прибирається на наступному злитті, крім найновішого розділу, який лишається за будь-якого віку.
  • Файл, записаний до появи акаунтів, не має accounts. Його buckets вважаються показниками акаунта unknown, доки наступне злиття не перенесе їх у цей розділ.
  • <state>/rate-limits.history.jsonl містить по одному такому запису на рядок: розділ, що змінився, з його account (null, коли акаунт невідомий), і ніколи не містить мапи accounts. Рядок без account або з мапою accounts записав PaceLine 0.2.5, і він може змішувати акаунти. pace враховує такий рядок, лише коли всі позначені рядки належать акаунту, у який увійдено.

pace датує файл за найстарішим живим bucket і за цим часом оцінює свіжість.

Inbox: формат для запису

Модуль PaceLine після кожного ходу моделі записує по одному показнику на сесію в <state>/inbox/<session id>.json, коли показники змінюються, а незмінний показник — щонайбільше раз на хвилину. Інший плагін може класти туди показники в тому самому форматі. Файли називати <plugin>-<id>.json, по одному на кожного автора запису й на кожну сесію, і перезаписувати лише власний файл.

{
  "observed_at": "2026-10-11T09:30:00.000Z",
  "session_id": "<session id>",
  "model": "<model id or null>",
  "account": "<account key, optional>",
  "five_hour": {"used_percentage": 42.5, "resets_at": "2026-10-11T12:00:00.000Z"},
  "seven_day": {"used_percentage": 18, "resets_at": "2026-10-16T03:00:00.000Z"}
}

Правила:

  • account необов'язкове і називає акаунт, якому належить показник. Програма, що записує показник і може назвати акаунт, має його вказувати. Показник без нього або зі значенням, що не є 16 шістнадцятковими цифрами в нижньому регістрі, потрапляє до розділу unknown, а програми, що читають файл, позначають такі показники як account unknown. Ключ обчислюється як перші 16 шістнадцяткових цифр хешу SHA-256 від тексту UTF-8 paceline-account-v1:<accountUuid>:<organizationUuid>, де обидва ідентифікатори взято з oauthAccount у .claude.json (див. Файли) у нижньому регістрі, а <organizationUuid> порожній, коли його немає. account не пишеться, коли accountUuid не є UUID. Ключ визначається перед кожним записом, а не один раз на процес, бо /login в іншій сесії змінює файл.
  • observed_at обов'язкове і датує обидва buckets. Bucket потребує числового used_percentage; resets_at — ISO 8601 або null.
  • Показник із майбутнього або з часом скидання, пізнішим, ніж дозволяє його вікно, пропускається.
  • Наполовину записаний файл читається як порожній до наступного злиття. Файл, старший за 7 днів, видаляється.
  • Правило злиття: пізніше вікно виграє; вікно, що минуло, програє будь-якому показнику; у межах одного вікна виграє вищий показник; за рівності лишається пізніший.

Програма, що читає власне використання акаунта, ті самі числа, що показує /usage, позначає свій показник як точний і може додати тижневі ліміти окремих моделей:

{
  "observed_at": "2026-10-11T09:30:00.000Z",
  "source": "usage-endpoint",
  "session_id": null,
  "model": null,
  "five_hour": {"used_percentage": 41, "resets_at": "2026-10-11T12:00:00.000Z"},
  "seven_day": {"used_percentage": 18, "resets_at": "2026-10-16T03:00:00.000Z"},
  "scoped": [{"name": "Fable", "used_percentage": 7, "resets_at": "2026-10-16T03:00:00.000Z"}]
}
  • Будь-яке значення source, крім usage-endpoint, або його відсутність позначає звичайний показник.
  • Злиття бере показники в порядку їхнього спостереження, незалежно від назв файлів.
  • Точний показник заміняє bucket з тією самою назвою, незалежно від його вікна і числа, якщо тільки bucket у файлі не є точним показником, зафіксованим пізніше, або звичайним показником, зафіксованим більш ніж на 15 хвилин пізніше. Звичайний показник відстає від акаунта на один запит, тож він не переважає точний показник, знятий за секунди чи хвилини до нього. Файли inbox читаються під час кожного злиття, тож ці 15 хвилин не дають старому точному показнику скасувати значно новіші. Точний показник, вікно якого минуло, не заміняє bucket вікна, яке ще триває.
  • Протягом 15 хвилин після точного показника звичайні показники не чіпають цей bucket, якщо тільки його вікно не минуло. Після цього знову діє правило злиття, тож свіжі точні показники треба надсилати й далі, щоб числа трималися.
  • scoped читається лише з точного показника, що має bucket seven_day. Його записи потребують рядкового name і числового used_percentage. Коли цей тижневий bucket виграє, scoped у файлі стає цим списком або видаляється, коли список порожній чи відсутній.

Злиття виконується на старті сесії і після кожного ходу, у фоні. Поки відкрита будь-яка сесія з PaceLine, зайнята чи в простої, злиття також виконується протягом приблизно 15 секунд після появи нового або зміненого файлу inbox. Команда pace запускає його, коли знаходить дані, старші за usage_snapshot_max_age_sec. Злиття тримає <state>/limits.lock, тож програми, що записують, працюють по черзі. PaceLine не потребує плагіна status line.

PreCompact, SessionStart (compact): cache_watch.py hook compactДо і після стиснення, ручного чи автоматичногоВимикає спостереження за сесією з причиною compacted; це також завершує її hook Stop, що чекає.

SessionStart: context_watch.py hook session-startСтарт сесіїВидаляє старі знімки, поки context-watch увімкнено.

PreToolUse (Agent, Workflow): pace_pre_agent.pyПеред кожним запускомДодає рядок pace:; на жорсткому ліміті просить підтвердження.
SubagentStart, SubagentStop: pace_subagent.pyСтарт і зупинка субагентаОтримує і звільняє резервування субагента.
SessionStart (startup, resume): pace_session_start.pyСтарт сесіїДодає непідтверджені плани, пропозицію пулу залишкових задач і підказку про часовий пояс.
SessionEnd: pace_session_end.pyЗавершення сесіїЗаписує завершення сесії в <state>/ended-sessions/ і звільняє її резервування; наступний виклик pace завершує перерване звільнення.

Чотири hooks pace одразу завершуються без виводу, поки pace вимкнено. Поки функцію вимкнено, її командні hooks однаково запускають один процес Python на кожну відповідну подію. Командні hooks запускають python3, якщо він працює, інакше python.
