Початок роботи з PaceLine

PaceLine має чотири функції. Одна працює від початку, решту вмикають за потреби. Жодна не додає вікна: усі говорять рядками в розмові.

КороткоПісля встановлення context-watch працює одразу. Команда /paceline:pace on вмикає бюджет на годину. pace не має вікна: у режимі limit він повідомляє моделі темп одним простим рядком перед кожним запуском Agent і Workflow, на жорсткому ліміті питає підтвердження і відповідає на /paceline:pace status.

Чотири функції, кожна вмикається окремо

Позначка показує стан одразу після встановлення.

context-watch

Увімкнено

Попередження перед автоматичним стисненням, знімок сесії під час кожного стиснення і необов'язковий індикатор контексту на кожному промпті.

/paceline:context-watch status

pace

Вимкнено

Бюджет на годину відносно п'ятигодинного і тижневого лімітів, розподілений по тижню за робочими та неробочими годинами, простий рядок pace для моделі перед кожним запуском Agent і Workflow у режимі limit та нічна черга без нагляду.

/paceline:pace on

usage-watch

Вимкнено

Кожні 125 секунд, поки відкрита хоч одна сесія, читає точне використання акаунта разом із тижневими лімітами окремих моделей, тож числа лишаються актуальними, коли сесії простоюють. Потрібен вхід через claude.ai. Числа належать акаунту, в який зараз виконано вхід, і змінюються після /login в інший акаунт.

/paceline:usage-watch on

cache-watch

Для кожної сесії

Будить сесію без активності незадовго до закінчення терміну її годинного кешу промпту, тож кеш зберігається на час відсутності.

/paceline:cache-watch on

Чи потрібен pace?

pace окупається, коли тижневий ліміт вичерпується до скидання, коли працює багато агентів, Workflows або нічних черг, або коли потрібно використати весь тижневий ліміт. Профіль підбирають за тим, що показують PitBoard або /usage.

Налаштування за чотири кроки

  1. Встановити плагін і почати нову сесію

    /plugin install paceline@agentpit

    context-watch починає працювати одразу. Потрібні Claude Code 2.1.287 або новіший і Python 3.9 або новіший; PitBoard не потрібен. Якщо PitBoard встановлено, його рядок показує ліміти, які записує PaceLine, з усіх сесій. Без PaceLine PitBoard показує ліміти лише так, як їх бачила його власна сесія.

  2. Увімкнути pace

    /paceline:pace on

    Відтепер запуск на жорсткому ліміті спершу запитує підтвердження, так само як і запуск, коли тижневе використання досягає межі зупинки тижневого резерву до його відкриття. У режимі limit кожен запуск Agent і Workflow також супроводжується рядком pace для моделі, а запуск, поки поточна частина понад свою частку, теж запитує підтвердження. /paceline:pace off вимикає це.

  3. Перевірити часовий пояс

    /paceline:pace profile set timezone Europe/Kyiv

    pace рахує робочі та неробочі години в поясі профілю. Новий профіль слідує за поясом цієї машини, тож нічого задавати не треба; /paceline:settings показує пояс, що використовується. Щоб натомість рахувати у фіксованому поясі, виконати наведену вище команду: вона переводить режим у fixed. Якщо підказка на старті сесії повідомляє, що Python не має даних для поясу цієї машини, встановити tzdata.

  4. Необов'язково: точне використання

    /paceline:usage-watch on

    Без нього числа беруться з останньої відповіді моделі в будь-якій сесії; з ним вони беруться з того самого джерела, що й /usage.

  5. Необов'язково: спланувати тиждень і обрати режим

    paceline plan

    paceline plan показує тиждень як робочі години (☼) і неробочі години (☾) кожного дня, кожні з позначкою і часткою залишку; paceline plan set позначає день. paceline mode обирає, що робить план: inform (типовий) лише показує його, limit змушує запуск понад частку поточної частини спершу просити підтвердження. У Claude Code Desktop вкладка Calendar у /paceline:settings pane показує дні тижня з їхніми позначками і частками; кнопки − і + змінюють частину, що ще не почалася.

pace не має вікна

Де видно pace

Один робочий день у тому порядку, в якому говорить pace. Рядки для агента показано так, як агент їх отримує.

Робочий день
  1. 08:05Старт сесії: нагадування
  2. 09:30Перед запуском Agent
  3. 11:00На запит: /paceline:pace status
  4. 15:40На жорсткому ліміті: запит підтвердження
  5. Наступного дня, 07:50Після ночі: звіт

Старт сесії: нагадування

Коли pace увімкнено, старт сесії нагадує агентові про часовий пояс, що відрізняється від поясу цієї машини. Більше нічого на старті сесії не додається.

Pace: This machine is in Europe/Madrid, but the pace profile counts in UTC. Run `paceline profile set timezone Europe/Madrid` to count in this machine's zone, `paceline profile set timezone_mode machine` to follow this machine as it changes, or `paceline profile set timezone UTC` to keep UTC. Tell the owner once.
Як читати
  • Агент повідомляє про це один раз; нічого не змінюється, доки не виконано одну з команд.

Перед запуском Agent

У режимі `limit` перед кожним запуском Agent або Workflow модель отримує один простий рядок. У режимі `inform` вона не отримує нічого, крім короткого тексту, коли захисна зупинка утримує запуск. Це контекст для моделі; коли pace не має даних про використання, рядок не додається.

pace (limit mode): on plan. This working-hours part has used 3.1 % of the week; its share is 9.0 % until 18:00, and 5.2 % by now would be on plan. Last 90 min about 0.8 %/h; the share allows about 1.5 %/h until 18:00. Over the share, each agent launch asks the owner first; do not retry a declined launch. No safety stop is near: week 47 % used, 5-hour window 41 %.
Як читати
  • on plan: робочі години витратили 3.1 % тижня, їхня частка до 18:00 — 9.0 %, а на цей момент на плані було б 5.2 %. Понад частку рядок каже, на скільки, і кожен запуск спершу запитує підтвердження.
  • Last 90 min about 0.8 %/h; the share allows about 1.5 %/h: недавній темп п'ятигодинного вікна в пунктах тижня порівняно з темпом, що завершує частину на її частці.
  • No safety stop is near: останнє речення називає п'ятигодинну межу або тижневий резерв і те, що станеться на ній, лише коли використання наблизилося до неї.

На запит: /paceline:pace status

Запустити /paceline:pace status або попросити агента показати стан pace. Агент виконує paceline status у Bash tool сесії; команда виводить цей рядок, а агент повідомляє бюджет і будь-яке попередження.

paceline status 7d 42% reset 2026-10-18 12:00+00:00 | budget 0.86%/h (working-hours norm 1.03) | forecast unused 12% | 5h 23%/95 | night 0.0% | data 0 min old
Як читати
  • forecast unused: скільки тижня лишилося б невикористаним за останнього темпу.
  • data 0 min old: наскільки свіжий показник використання. STALE означає старше 30 хвилин; тоді жорсткі ліміти вікон не застосовуються, і нічна черга чекає.

На жорсткому ліміті: запит підтвердження

На жорсткому ліміті запуск зупиняється і запитує підтвердження: від 95% п'ятигодинного вікна (`five_hour_stop_pct`) або коли тижневий ліміт вичерпано. Доки тижневий резерв не відкрито, запуск також запитує підтвердження, щойно тижневе використання досягає 100% мінус резерв (92% за типового 8%); `paceline reserve` показує і задає його. Причина стоїть на початку опису інструмента, тож її видно на кожній поверхні запитів.

[pace hard limit: 5h window 96% >= 95% stop, resets 2026-10-14 18:00+00:00] Explore the payment module pace hard limit: 5h window 96% >= 95% stop, resets 2026-10-14 18:00+00:00. Launch Agent anyway? Yes / No
Як читати
  • Yes однаково запускає агента; No лишає агентові чекати або працювати без субагента.
  • Більше нічого не блокується: pace питає лише перед запусками.

Після ночі: звіт

Якщо залишити нічну чергу працювати, агент складає ранковий звіт за шаблоном PaceLine: що зроблено, що відкладено і чому, питання до власника, витрати порівняно з оцінками.

## Done - Q3: Update the release notes (agentpit-dev): merged ## Deferred - Q5: Rename the store keys: deferred after 3 attempts, gate failed ## Night budget - Allowance: 5.0% (the off-hours share of 2026-10-14)
Як читати
  • Кожен рядок можна простежити до елемента черги, утримання або позначки часу статусу.
  • Черга стартує лише після явного запуску; сама вночі нічого не запускається.
