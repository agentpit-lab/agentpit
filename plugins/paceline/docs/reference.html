PaceLine reference

Commands, exit codes, profile keys, environment variables, files, and the formats other programs read and write. The tables come from the plugin's code: python .ci/docs_facts.py build writes its facts, and python .ci/pages.py build writes the tables from them. The notes under each table are hand-written.

In this page, <state> is the state directory: $PACELINE_STATE_DIR, else <config>/state/paceline, where <config> is $CLAUDE_CONFIG_DIR, else ~/.claude.

Inside a session, the paceline command is on the PATH of the Bash tool. Elsewhere, run <plugin dir>/bin/paceline.cmd on Windows, or python <plugin dir>/scripts/paceline.py.

Common options

Every command except away, cache-watch, context-watch, and usage-watch accepts these options:

  • --json: print the full result as JSON.
  • --model ID: the current model ID. It selects a model-scoped weekly bucket when the limits file has one. Default: $PACELINE_MODEL, else $ANTHROPIC_MODEL.
  • --session ID: the Claude Code session ID. Default: $CLAUDE_SESSION_ID.
  • --no-merge: use the limits file as it is, without merging the inbox first.
  • --now TIME: an ISO 8601 time to use as the clock, for what-if runs and tests. Default: $PACELINE_NOW, else the real time.
  • --state-dir DIR: the state directory for this command.

Status and switches

  • paceline status prints one line, for example:

    7d 34% reset 2026-10-03 03:00+00:00 | budget 1.45%/h (weekday norm 1.03) | agents <=3 model opus | 5h 23%/80 | night 15.2% | data 1 min old

    The fields, in order: weekly usage with any model-scoped buckets and the local reset time; the budget per hour against the norm for the same kind of hour (the weekday rate is added when it differs from the budget); forecast unused, when there is enough history; the advised parallel agents and model; five-hour usage against the current threshold; the night allowance; the age of the data, with STALE in front when it is older than stale_threshold_min. Further fields appear only when they apply: account unknown (<reason>), when the figures cannot be told to be the signed-in account's (the reasons are untagged, no-file, unreadable, and no-account), other account <8 digits> active; --account <8 digits>, one entry for each other account with a reading under 30 minutes old, shown only when the key came from .claude.json (neither the account variables nor --account named it), host memory unknown, pace hooks off (paceline on), a WARNING that the rest of the week is near the day hours' capacity, the reasons for a block, pause, throttle, or five-hour burn (for example 5h burn 42.7%/h vs budget 13.9%/h: 80% at <time>, before reset <time>), unconfirmed plans that start tomorrow, and the leftover-pool suggestion. The explanation says how each number is computed. With --json, data.account is {"state": "known" | "unknown", "key": <the signed-in account's key or null>, "reason": <code or null>}; key is the one-way key of the inbox, never an identifier of the account. data.other_accounts, a list of the full keys behind the other account field, is present only when that field is shown. paceline status --account KEY reports the partition whose key starts with KEY, 4 to 16 hex digits of a key in rate-limits.json; no match or several matches exit with code 2 and list the candidate keys. --account belongs to status alone; the gates and the night queue always use the account of the session.

  • paceline auto [--start-run] prints the parameters for the next night-queue item, for example auto: START Q3 | budget 4.20% | agents <=3 models opus,sonnet,haiku, and exits 0 (start), 10 (wait), or 11 (stop). --start-run begins tonight's run: it fixes the night allowance and the weekly usage it counts from. Running it again in the same night keeps that run. With --json, the result has action, next_item, budget_for_next_item_pct, max_parallel_agents, max_heavy_runs, allowed_models, wait_until, and reasons. At any hour, auto projects the five-hour burn rate to the night threshold and lowers max_parallel_agents; when the cap reaches 0, auto waits and wait_until is the five-hour reset. A run remembers the account it started under. When another account is signed in, auto stops with the reason account changed during the run, checked before every other stop; when the account cannot be resolved, it waits with account unknown.
  • paceline on and paceline off write the pace switch, <state>/pace.json.
  • paceline calibrate reads the limits history and the completed reservations and proposes new values for five_hour_to_week_pct, reserve_pct, weekend_cap_pct, night_base_pct, and subagent_estimate_pct, plus a ratio of actual to estimated cost for your task estimates. It needs calibration_min_days days of history and changes nothing.
  • paceline profile prints the profile; show is the default. paceline profile set KEY VALUE changes one key with checks (see Profile keys). paceline profile check compares the profile's time zone with this machine's and prints a hint when they differ.
  • paceline merge [--verbose] merges the inbox into the limits file now. It prints nothing unless you pass --verbose or --json.
  • paceline doctor [--live] [--bundle PATH] diagnoses PaceLine on this machine. It runs these probes: runtime, paths, switch, inbox, limits, account, process, memory, timezone, hooks, and debug_log, each ok, warn, or fail, with a hint for some. The account probe reports known or unknown and a reason code (no-file, unreadable, no-account), and nothing from .claude.json. --json shows the evidence of each probe. Without --live it changes nothing; --live also runs one merge. --bundle writes a zip with the report, the debug log, the profile, the pace switch, the limits file, the last 50 history lines, and the last 20 reservations. The report and the bundle write your home directory as ~. The bundle holds the plan phrases you typed, reservation labels, and session IDs.
  • paceline status --json shows the burn rule under five_hour.burn (rate_per_hour_pct, budget_per_hour_pct, budget_share, threshold_pct, threshold_at, threshold_at_local, base_at, span_min, and limited; null while no rate is measured), the cap under recommendation.five_hour_burn_limited, and the away marker under away (on, set_at, session). paceline status --launch-key KEY also holds a short-lived launch reservation under that key; the Agent and Workflow hook passes the tool call ID.

Plans

  • paceline plan add --type away|heavy --from DATE --to DATE [--weight W] [--phrase TEXT] declares a future absence (away) or heavy day (heavy). A date is YYYY-MM-DD, today, tomorrow, or an ISO 8601 date and time, in the profile's time zone. A bare date as --to includes that whole day. The weight defaults to 0 for away and to heavy_weight for heavy. --phrase keeps your own words, so a later find --text can match them. Plan IDs are P1, P2, and so on.
  • paceline plan list lists every declared plan.
  • paceline plan find [--text TEXT] [--on DATE] [--type away|heavy] lists the plans whose phrase contains the text, that overlap that day, or that have that type. It exits 0 for one match, 3 for several, and 4 for none.
  • paceline plan modify ID [--from DATE] [--to DATE] [--weight W] [--phrase TEXT] changes a plan and clears its confirmation.
  • paceline plan cancel ID removes a plan.
  • paceline plan confirm ID marks a plan confirmed today. The session-start reminder then stops for it. The budget does not change.
  • paceline plan tomorrow lists the plans that start tomorrow and are not confirmed today.

add, modify, and cancel end their line with the new budget, for example plan P4 away 2026-10-16 00:00+02:00 .. 2026-10-17 00:00+02:00 added; budget 1.21%/h, night 5.0%. Plans that have ended are removed by the next command.

Reservations

  • paceline reserve acquire --kind subagent|workflow|gate|queue [--estimate PCT] [--label TEXT] [--key KEY] [--pid PID] [--item ID] holds a reservation. --estimate is the expected cost in percent of the weekly limit; it is required for every kind except subagent, which defaults to subagent_estimate_pct. With --key, a session holds one reservation per key, and a repeated acquire renews it. --pid is the owning Claude Code process; the default is the nearest parent process whose name starts with claude. Reservation IDs are R- and eight hex digits.
  • paceline reserve renew ID renews a lease. It exits 4 when the reservation has expired or was released.
  • paceline reserve release [ID] [--key KEY] [--actual PCT] releases one reservation, named by ID or by key. The actual cost defaults to the change in weekly usage since the reservation was acquired. It exits 4 when there is nothing to release.
  • paceline reserve release-session [--target-session ID] releases every reservation of a session, by default the one in --session.
  • paceline reserve prune drops reservations whose lease expired or whose process is gone.
  • paceline reserve list lists the active reservations.
  • paceline reserve reconcile summarizes completed reservations by kind: count, estimated and actual sums, and the median ratio of actual to estimate.
  • A reservation of kind launch is not acquired with reserve acquire. paceline status --launch-key KEY holds it, in the same lock hold that counts the active reservations. It carries no estimate, never reaches the completed reservations, and ends after 60 seconds. reserve acquire --kind subagent closes the oldest launch reservation of the same session, and reserve release --key KEY --session ID drops one by hand; both the key and the session must be those of the launch. reserve list shows it.

A reservation is dropped when its lease expires (lease_ttl_min without a key, agent_lease_ttl_min with one) or when its process is gone. A completed reservation records overlapped when another reservation ran at the same time: its measured cost is a change in account-wide weekly usage, so parallel work inflates it.

Night queue and leftover pool

Every paceline queue command works on the night queue, or with --pool on the leftover pool. Queue item IDs are Q1, Q2, and so on; pool item IDs are L1, L2, and so on. An item is pending, running, done, or deferred.

  • add --title TEXT --repo NAME --estimate PCT [--independent] [--depends ID,ID] adds an item. --independent lets it run beside other independent items. Every dependency must already exist.
  • list lists the items. report summarizes the current run: done, deferred, running, and pending items, with the sums of their estimates and actual costs.
  • approve (pool only) approves the pool for the current weekly window.
  • start ID [--pid PID] marks a pending item running and holds a queue reservation for it.
  • done ID [--actual PCT] marks it done; the actual cost defaults to the change in weekly usage since it started.
  • fail ID [--reason TEXT] counts one failed fix of the item's checks. At gate_fix_attempts failures, the item is deferred.
  • defer ID [--reason TEXT] defers the item; the default reason is needs owner permission.
  • retry ID puts an item back to pending and resets its failure count.
  • remove ID deletes an item. It is refused while a pending or running item depends on it.
  • clear-done deletes the done items.

Deferring an item, by defer or by the last fail, also defers every pending or running item that depends on it.

cache-watch

  • paceline cache-watch on --session ID --data-dir DIR [--lead MIN] [--max N] watches one session. It exits 3 and prints not started with the reason when it finds no transcript for the session, no one-hour cache entry yet, or five-minute cache entries. cache-watch holds only the one-hour prompt cache; when the main thread switches to five-minute entries while watching, it stops itself, and status shows the session as off (five-minute cache). After the session line, on prints two lines on what a wake costs: the context size, and that a rewrite of the context after the cache expired costs at least 20 times a wake's cache read. See limitations.
  • paceline cache-watch off --session ID --data-dir DIR stops watching a session.
  • paceline cache-watch status --data-dir DIR lists every watched session: on or off and why (operator, five-minute cache, no reply after N wakes, compacted, cache expired before the wake), the wakes so far, the cache expiry, and the next wake. It removes the state of sessions whose transcript has not changed for 24 hours.
  • paceline cache-watch config --data-dir DIR [--lead MIN] [--max N] shows or changes the defaults: lead is 5 minutes (1 to 30), and max is 5 wakes (1 to 20). --lead and --max on on apply to that session only. A wake comes lead minutes before the cache expires, and no later than 52.5 minutes after the last request.

The data directory is the plugin's ${CLAUDE_PLUGIN_DATA}. The skill /paceline:cache-watch fills in the session ID and the data directory.

context-watch

  • paceline context-watch status [--project DIR] prints the settings, the project's snapshot folder with its number of snapshots, and the settings file.
  • paceline context-watch config [--on|--off] [--line on|off] [--levels 85,95] [--days N] shows or changes the settings. --off turns off the line, the warnings, and the snapshots. --line on adds the line to every prompt; --line off hides it, which is the default. Levels are ascending whole percents from 50 to 99. Snapshots are kept 1 to 90 days. Changes apply from the next prompt.

Defaults: on, line off, warnings at 85% and 95%, snapshots kept 14 days.

usage-watch

  • paceline usage-watch on and paceline usage-watch off write the switch, <state>/usage-watch.json.
  • paceline usage-watch status prints the switch, the account whose state it reports (account: <key>, or account: unknown when none is known), the last attempt, the last success, and the last error of that account. Times are ISO 8601 in UTC, or never.

away

  • paceline away on [--session ID] sets the away marker, <state>/away.json, for every session. It prints away: on since <time> and a note that a launch that would ask for confirmation is now denied. The skill passes the session ID.
  • paceline away off clears the marker and prints away: off.
  • paceline away status prints away: off, or away: on since <time> and the session that set it.
  • The hooks module clears the marker at prompt.submit on your next message in any session. A prompt from a schedule or a loop, a notification, another session, a channel, a plugin, claude -p or the Agent SDK leaves it, and so do a cache-watch wake and the /paceline:away command, in its raw form (/paceline:away or /away), expanded into a <command-name> tag, or as the command Claude Code names.

away takes no common option. While the marker is set, the Agent and Workflow hook denies a launch that would ask. paceline status --json shows the marker under away. See The away marker.

  • 0: success. paceline merge also exits 0 when another merge holds the lock.
  • 1: an error, with the message on stderr as paceline: .... Examples: no usage data yet, an unknown plan or item ID, a state file that is not valid JSON (PaceLine leaves it for you to fix), or pace.lock busy for 20 seconds. A refused cache-watch or context-watch value also exits 1.
  • 2: an invalid command line, or a value that paceline profile set refused. A refused value changes nothing.
  • 3: plan find found several plans. cache-watch on uses 3 for not started.
  • 4: plan find found no plan, or reserve renew or reserve release found no reservation.
  • 10 and 11: auto says wait or stop.

The profile is <state>/pace-profile.json. The first paceline command creates it. A new profile takes this machine's time zone when Python can use that zone here, and records it as confirmed; otherwise it keeps UTC. Keys missing from the file are filled with their defaults when it is read. version, plans, next_plan_id, and timezone_confirmed are kept by PaceLine and are not in the table.

paceline profile set KEY VALUE reads VALUE as JSON when it parses, else as text. The value must have the key's type and range: percentages from 0 to 100, counts and sizes not negative, hours as [start, end] with 0 <= start < end <= 24, reserve_decay_start as a weekday from 0 to 6 and an hour from 0 to 23, model lists not empty, and a time zone Python can use here. A refused value exits 2 with the reason on stderr. On success it prints KEY: OLD -> NEW and the paceline status line. Setting timezone also sets timezone_confirmed to true. You can still edit the file by hand; the checks do not apply to a hand edit.

What each key does:

  • timezone: the IANA zone every wall-clock rule uses, for example America/New_York.
  • day_hours: the day hours, start inclusive, end exclusive. Only day hours get a budget.
  • night_hours: the night hours, when the night queue runs. An hour in neither range is an off hour and gets no budget.
  • weekday_weight, weekend_weight: the relative weight of a weekday and a weekend day hour.
  • weekend_cap_pct: the most of the week, in percent, that the weekend day hours may spend together.
  • reserve_pct: the share of the week held back until the reserve starts to fall.
  • reserve_decay_start: when the reserve starts to fall, as {"weekday": W, "hour": H} in local time; Monday is 0. The default is Friday 18:00.
  • five_hour_threshold_day, five_hour_threshold_night: five-hour usage, in percent, at which background work pauses and an Agent or Workflow launch asks you first. The five-hour burn rate is projected to the same threshold.
  • five_hour_hard_stop: five-hour usage at which the recommendation starts nothing new.
  • five_hour_to_week_pct: the share of the week that one full five-hour window costs. It sets the most any hour can get: this value divided by 5, in percent of the week per hour. paceline calibrate proposes a measured value.
  • heavy_weight: the default weight of a heavy plan.
  • night_base_pct: the night allowance before any surplus is added.
  • host_night_capacity_pct: an optional cap on the night allowance; null means none.
  • lease_ttl_min, agent_lease_ttl_min: the lease of a reservation without and with a key, in minutes.
  • subagent_estimate_pct: the estimated cost of one subagent, in percent of the week.
  • stale_threshold_min: data older than this many minutes is stale.
  • usage_snapshot_max_age_sec: a command that finds the data older than this many seconds merges the inbox first.
  • capacity_warn_ratio: paceline status warns when what remains of the week reaches this share of what the remaining day hours can spend.
  • auto_refresh_five_hour_pct, auto_refresh_cache_sec: at or above this five-hour usage, auto merges the inbox first when the data is older than this many seconds.
  • min_free_commit_mb: free memory, in MiB, below which no new work starts.
  • commit_reserve_mb, heavy_job_mb, max_heavy_runs: the heavy runs allowed are min(max_heavy_runs, (free memory - commit_reserve_mb) // heavy_job_mb), and never fewer than 0.
  • max_agents: the most parallel agents pace recommends.
  • models: model families in order of preference.
  • routine_models: the models for routine work while the recommendation throttles.
  • throttle_weekly_pct: weekly usage from which the recommendation throttles, while more than 24 hours remain to the reset.
  • scoped_exhausted_pct: a model-scoped weekly bucket at this level removes its model from the allowed models. Model-scoped buckets come only from usage-watch.
  • leftover_suggest_pct: the forecast unused share above which pace suggests a leftover pool.
  • gate_fix_attempts: failed fixes before a queue item is deferred.
  • calibration_min_days: the days of history paceline calibrate needs.

The limits file (for readers)

<state>/rate-limits.json holds the newest limit readings from every session on this machine. A status line plugin or any other program may read it. Its format:

{
  "observed_at": "2026-10-11T09:30:00.000Z",
  "source": "payload",
  "session_id": "<session that gave the newest reading>",
  "model": "<its model id or null>",
  "five_hour": {"used_percentage": 42.5, "resets_at": "2026-10-11T12:00:00.000Z",
                "observed_at": "2026-10-11T09:30:00.000Z", "source": "payload"},
  "seven_day": {"used_percentage": 18, "resets_at": "2026-10-16T03:00:00.000Z",
                "observed_at": "2026-10-11T09:28:00.000Z", "source": "payload"},
  "account": "069e3589b134b882",
  "accounts": {
    "069e3589b134b882": {"observed_at": "2026-10-11T09:30:00.000Z", "source": "payload", "...": "..."},
    "9f44059c413565ef": {"observed_at": "2026-10-10T18:02:00.000Z", "source": "payload", "...": "..."}
  }
}

The fields above account are the newest partition, copied to the top level. A reader that knows nothing of accounts reads them as before.

  • observed_at is the newest bucket time; each bucket carries its own. Times are ISO 8601 in UTC.
  • resets_at is rounded to the minute and may be null.
  • Either bucket may be absent. Ignore fields you do not know.
  • A bucket's source is payload (a session's reading) or usage-endpoint (an exact reading of the account's usage). The top-level source is that of the newest bucket.
  • scoped, when present, is a list of {"name", "used_percentage", "resets_at"?} model-scoped weekly buckets. It comes only with an exact weekly reading and is replaced by the next one. It is dropped when seven_day moves to another window without one.
  • The file is replaced through a temporary file and a rename, so a reader never sees a partial file. It is written only when it changes.
  • accounts maps an account key to that account's record, in the format above without account and accounts. A key is 16 lower-case hex digits, or unknown for readings with no account. Each partition is merged on its own. A reader that knows the account it serves reads accounts[<its key>], else accounts["unknown"] and says that the account is unknown, and never another account's partition.
  • account is the key of the partition copied to the top level, or null when that partition is unknown.
  • A partition that no reading has touched for 7 days is dropped at the next merge, except the newest partition, which stays however old.
  • A file written before accounts existed has no accounts. Its buckets count as readings of the unknown account until the next merge moves them into that partition.
  • <state>/rate-limits.history.jsonl holds one such record per line: the partition that changed, with its account (null when unknown), and never the accounts map. A line with no account, or with an accounts map, was written by PaceLine 0.2.5 and may mix accounts. pace counts such a line only while every tagged line is the signed-in account's.

pace dates the file by its oldest live bucket, and judges freshness from that time.

The five-hour burn file (for readers)

<state>/five-hour-burn-<key>.json holds the burn figures of the current five-hour window of the account with that key (16 lower-case hex digits, the key of the limits file), computed once for every reader. With two accounts in use at once each has its own file. A reader that serves one account reads its own file. PitBoard reads it; any other program may. The format is:

{
  "computed_at": "2026-10-16T16:10:00.000Z",
  "account": "069e3589b134b882",
  "used_pct": 40,
  "resets_at": "2026-10-16T20:45:00.000Z",
  "threshold_pct": 80,
  "budget_per_hour_pct": 8.727,
  "rate_per_hour_pct": 42.7,
  "threshold_at": "2026-10-16T17:06:12.365Z",
  "threshold_at_local": "2026-10-16 20:06+03:00",
  "base_at": "2026-10-16T15:50:00.000Z",
  "span_min": 20.0,
  "limited": true
}

The fields:

  • computed_at is when PaceLine computed the figures. Times are ISO 8601 in UTC with milliseconds, except threshold_at_local, which uses the profile's time zone.
  • account is the key of the account the window belongs to, the same key as in the limits file.
  • used_pct and resets_at are the five-hour percentage and reset time the figures were computed for.
  • threshold_pct is the threshold of the hour of computed_at: 80% by day and 95% at night by default. budget_per_hour_pct is the even pace that reaches it at the reset.
  • rate_per_hour_pct, threshold_at, threshold_at_local, base_at, and span_min are null while no rate is measured; threshold_at and threshold_at_local are also null at a rate of 0 and at or above the threshold.
  • limited is true in the burn state: the rate would reach the threshold before the reset, and the data is fresh.

Use a file only when all of these hold: account is the account you serve; resets_at and used_pct equal the five-hour figures you show; computed_at is at most 3 minutes old. Otherwise compute your own projection. At or above the threshold the file projects nothing.

PaceLine writes the file only while pace is on, only for a known account and a known reset, after every merge that the plugin's hooks run and that wrote the limits file, and from every command that computes the status on the real clock. paceline merge on its own does not write it. A run dated with --now or PACELINE_NOW more than 5 minutes from the real time writes nothing, and neither does paceline status --account. The file is replaced through a temporary file and a rename. The file of an account that is no longer used stays, under 1 KB, until the account's next use replaces it. PaceLine never reads the file back: its own history is the only input of its computation.

The inbox (for writers)

PaceLine's module writes one reading per session to <state>/inbox/<session id>.json after each model turn when the readings change, and an unchanged reading at most once a minute. Another plugin may drop readings there in the same format. Name your files <plugin>-<id>.json, one per writer and session, and overwrite your own file.

{
  "observed_at": "2026-10-11T09:30:00.000Z",
  "session_id": "<session id>",
  "model": "<model id or null>",
  "account": "<account key, optional>",
  "five_hour": {"used_percentage": 42.5, "resets_at": "2026-10-11T12:00:00.000Z"},
  "seven_day": {"used_percentage": 18, "resets_at": "2026-10-16T03:00:00.000Z"}
}

Rules:

  • account is optional and names the account the reading belongs to. A writer that can name the account should set it: a reading without it, or with a value that is not 16 lower-case hex digits, goes to the partition unknown, and readers mark those figures account unknown. Compute the key as the first 16 hex digits of the SHA-256 hash of the UTF-8 text paceline-account-v1:<accountUuid>:<organizationUuid>, with both identifiers lower-cased from oauthAccount in .claude.json (see Files) and <organizationUuid> empty when it is missing. Write no account when accountUuid is not a UUID. Resolve it before every write, not once per process, because a /login in another session changes the file.
  • observed_at is required and dates both buckets. A bucket needs a numeric used_percentage; resets_at is ISO 8601 or null.
  • A reading from the future, or with a reset later than its window allows, is skipped.
  • A half-written file reads as nothing until the next merge. A file older than 7 days is deleted.
  • Merge rule: the later window wins; a window that has passed loses to any reading; within one window the higher reading wins; a tie keeps the later one.

A writer that reads the account's own usage, the figures /usage shows, marks its reading as exact and may add the model-scoped weekly limits:

{
  "observed_at": "2026-10-11T09:30:00.000Z",
  "source": "usage-endpoint",
  "session_id": null,
  "model": null,
  "five_hour": {"used_percentage": 41, "resets_at": "2026-10-11T12:00:00.000Z"},
  "seven_day": {"used_percentage": 18, "resets_at": "2026-10-16T03:00:00.000Z"},
  "scoped": [{"name": "Fable", "used_percentage": 7, "resets_at": "2026-10-16T03:00:00.000Z"}]
}
  • Any source other than usage-endpoint, or none, marks an ordinary reading.
  • The merge takes the readings in the order they were observed, whatever their file names.
  • An exact reading replaces the bucket of the same name, whatever its window and number, unless the bucket in the file is an exact reading observed later, or an ordinary reading observed more than 15 minutes later. An ordinary reading lags the account by one request, so it does not outrank an exact reading taken seconds or minutes before it. Inbox files are read at every merge, so the 15 minutes keep an old exact reading from undoing much newer ones. An exact reading whose window has passed does not replace a bucket of a window still running.
  • For 15 minutes after an exact reading, ordinary readings leave that bucket alone, unless its window has passed. After that the merge rule applies again, so keep posting fresh exact readings for your numbers to stay.
  • scoped is read only from an exact reading with a seven_day bucket. Its entries need a string name and a numeric used_percentage. When that weekly bucket wins, the file's scoped becomes this list, or is removed when the list is empty or absent.

The merge runs when Claude Code starts and then every 15 seconds while the inbox changed, in the background.
