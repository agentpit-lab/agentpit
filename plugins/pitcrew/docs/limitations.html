PitCrew limitations

Surfaces and requirements

Requirements: Claude Code 2.1.287 and Python 3.9

PitCrew needs Claude Code 2.1.287 or later, and Python 3.9 or later on PATH as python3 or python.

with neither python3 nor python on PATH, a hook reports an error and pitcrew does not run. A Python older than 3.9 is not supported.

everything else in Claude Code. See Reference.

Alongside PaceLine

PaceLine 0.6.0 or earlier runs its own copy

PaceLine 0.6.0 and earlier carry their own copy of context-watch and cache-watch. With both plugins installed, both copies run:

  • each prompt past a warning level gets two warnings, one from each plugin;
  • each compaction writes two snapshots, .claude/pitcrew/<session id>.md and .claude/paceline/<session id>.md;
  • a session watched with both /pitcrew:cache-watch on and /paceline:cache-watch on has two waiters.

PitCrew does not look for PaceLine's copy, so it keeps running beside it. With both installed, PitCrew's session-start cleanup also removes PaceLine's snapshots older than PitCrew's own snapshot days.

the agent hears each warning twice and finds two snapshots after a compaction.

run one copy. A PaceLine release that moved the watchers to PitCrew has no copy left; before that, turn one of them off as Run only one copy of the watchers while PaceLine has its own describes.

A session watched under PaceLine is not watched under PitCrew

cache-watch keeps the state of each watched session in the data directory of the plugin that started it. PitCrew does not carry over a session that was watched under PaceLine. The defaults, lead_minutes and max_wakes, and context-watch's settings do carry over: PitCrew reads PaceLine's files until it writes its own.

a session that /paceline:cache-watch on watched is not watched by PitCrew. Once PaceLine no longer carries cache-watch, nothing watches it.

run /pitcrew:cache-watch on in the session to watch it under PitCrew. See Hold the cache while away.

context-watch

context-watch leaves subagent compactions alone and gives no warnings with auto-compaction off

context-watch leaves subagent compactions alone: it writes a snapshot only for the main conversation. With auto-compaction off, the context line, if you turned it on, measures against the context window, and no warnings come.

no snapshot for a subagent's compaction, and no warning at 85% or 95% while auto-compaction is off.

the line, if you turned it on, and a snapshot at each compaction of the main conversation. See Recover after a compaction.

Where an organization manages Claude Code, context-watch does not run

On a Team or Enterprise login, and on a machine with managed settings, Claude Code seats its built-in sec-default guard. The guard keeps the prompt, tool-batch, session-start and compaction events from the hooks module of a plugin you install, and context-watch runs on those events.

no context line, no warnings at the set levels, no snapshot at a compaction, and no note after it to read one.

cache-watch, which runs on command hooks. PitCrew is not covered by the tools that seat PaceLine as an organization's plugin yet.

cache-watch

cache-watch keeps only one-hour cache entries

cache-watch holds the one-hour prompt cache. A session whose main thread writes five-minute cache entries is refused.

on prints not started: this session writes five-minute cache entries; cache-watch keeps only one-hour entries.

the main thread's TTL is Claude Code's setting for the session. See Hold the cache while away.

cache-watch keeps only the main thread's cache

cache-watch keeps only the main thread's cache. It reads the session's own transcript and skips subagent rows; subagents write their rows to separate files. A wake refreshes the main thread's cache and never a subagent's. Only the main thread's cache entries decide whether a session is watched: a session whose main thread writes five-minute entries is refused even when its subagents write one-hour entries.

a finished subagent that you resume after its cache expired starts cold, whatever its TTL.

the main conversation stays warm while cache-watch is on.

cache-watch needs a cache entry first

cache-watch starts only after the main thread has written a cache entry, which tells it the TTL.

on in a session with no cache entry yet prints not started: this session has no one-hour cache entry yet.

take one turn in the session, then run on again.

cache-watch does nothing in non-interactive runs

cache-watch keeps no cache in claude -p runs. Its wake is a background Stop hook, and Claude Code kills a background hook that is still running when a -p run ends. Ending the session also removes the session's cache-watch state. Sessions of the Agent SDK are not tested.

the run ends after its turn, and no wake comes.

cache-watch in an interactive session, in the CLI or in Desktop. See Hold the cache while away.

A computer that sleeps past the cache's expiry loses the cache

The wake runs in a hook process on this computer. A computer that sleeps past the cache's expiry misses the wake. cache-watch then turns itself off for the session, and your next message brings a one-line notice.

after the computer wakes, your next turn writes the whole context to the cache again, and the agent tells you in one line that the cache expired before the wake and cache-watch is off. /pitcrew:cache-watch status shows off (cache expired before the wake).

run /pitcrew:cache-watch on to watch the session again, or keep the computer awake while you are away.

Each wake counts against the five-hour limit

Each wake is one turn: it reads the context from the cache and sends a one-line push. The read costs far less than the rewrite of the whole context that the first turn after the cache's expiry would make (at least 20 times less by Anthropic's API prices), but the turn still counts against the five-hour limit. How much a cache read weighs in subscription limits is not published.

at most max (5) wake turns per absence, with the default settings.

lower --max, or raise --lead, with /pitcrew:cache-watch config. See Hold the cache while away.

The push reaches a phone only with Remote Control

The wake sends its one-line message as a push only when the session has the push tool: with Remote Control on and "Push when Claude decides" enabled in /config.

without them, no push on your phone.

without the push tool, the wake posts the line in the session as a reply instead.

cache-watch stops itself when the main thread switches to five-minute entries

When the main thread starts writing five-minute cache entries while cache-watch is on, watching stops.

one wake tells you in one line that cache-watch stopped, and /pitcrew:cache-watch status shows off (five-minute cache).

once the main thread writes one-hour entries again, run on again.

cache-watch shows times in the machine's time zone

The Cache kept until line and the times in status use the machine's time zone.

they can differ from the times another tool shows when it counts in another zone.

only the printed clock times use the machine's zone.

Idle compaction can run after cache-watch's last wake

In a terminal session whose context is at or above the idle compaction threshold, Claude Code is expected to compact the conversation about 54 minutes after the last request (Claude Code, settings reference, read 2026-10-15). cache-watch wakes the session no later than 52.5 minutes after the last request, and each wake, as a new request, restarts Claude Code's idle count. When the wakes run out, cache-watch turns itself off and Claude Code can compact about 54 minutes after the last wake. The threshold is 200,000 tokens unless CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS sets it, and idle compaction also needs Claude Code to fetch feature flags from Anthropic, so a given session may differ.

/pitcrew:cache-watch status shows off (no reply after N wakes). If Claude Code compacted the session in the meantime, the next message in the session sends a summary instead of the full history.

run /pitcrew:cache-watch on to watch the session again, or raise the number of wakes with --max. Setting idleCompaction to false keeps Claude Code v2.1.290 or later from compacting while idle; on an earlier version, setting autoCompactEnabled to false does. See Choose between cache-watch and idle compaction.

cache-watch depends on Claude Code's private transcript format

cache-watch reads the session transcript, a private file of Claude Code, for the main thread's cache writes and their TTL.

if the format changes, on can report no one-hour cache entry, or wakes can stop.

context-watch does not read the transcript.
