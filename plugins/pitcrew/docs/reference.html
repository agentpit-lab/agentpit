PitCrew reference

Every command, setting, file, environment variable, exit code and hook of PitCrew. For tasks, see the how-to guides; for what it cannot do, see the limitations.

Commands

pitcrew runs in the session's Bash tool, where PitCrew puts it on the PATH; the skills run it for you. Run with no argument or with an unknown group, it prints a usage text that names both groups and exits 2. If pitcrew is not found, run python "${CLAUDE_PLUGIN_ROOT}/scripts/pitcrew.py" with the same arguments. The table is read from the plugin's own command parser.

CommandWhat it does
pitcrew context-watchwarnings before auto-compaction, snapshots at each compaction
pitcrew context-watch configshow or change context-watch's settings
pitcrew context-watch statusshow the settings, the snapshot folder and the settings file
pitcrew cache-watchkeep an idle session's one-hour prompt cache alive
pitcrew cache-watch onwatch one session
pitcrew cache-watch offstop watching one session
pitcrew cache-watch statuslist the watched sessions
pitcrew cache-watch configshow or change the defaults for every session

cache-watch commands

  • pitcrew cache-watch on --session ID --data-dir DIR [--lead MIN] [--max N] watches one session; DIR is the plugin's data directory, where the session's state lives. It exits 3 and prints not started with the reason when it finds no transcript for the session, no one-hour cache entry yet, or five-minute cache entries. cache-watch holds only the one-hour prompt cache; when the main thread switches to five-minute entries while watching, it stops itself, and status shows the session as off (five-minute cache). After the session line, on prints two lines on what a wake costs: the context size, and that a rewrite of the context after the cache expired costs at least 20 times a wake's cache read. See limitations.
  • pitcrew cache-watch off --session ID --data-dir DIR stops watching a session.
  • pitcrew cache-watch status --data-dir DIR lists every watched session: on or off and why (operator, five-minute cache, no reply after N wakes, compacted, cache expired before the wake), the wakes so far, the cache expiry, and the next wake. It removes the state of sessions whose transcript has not changed for 24 hours.
  • pitcrew cache-watch config [--lead MIN] [--max N] shows or changes the defaults: lead is 5 minutes (1 to 30), and max is 5 wakes (1 to 20). It prints defaults: lead 5 min · max 5 wakes without a reply, and writes <state>/cache-watch.json only when an option is given. --lead and --max on on apply to that session only. A wake comes lead minutes before the cache expires, and no later than 52.5 minutes after the last request.

The data directory is the plugin's ${CLAUDE_PLUGIN_DATA}; it holds the state of each watched session. The defaults are not there: they are in <state>/cache-watch.json. The skill /pitcrew:cache-watch fills in the session ID and the data directory.

context-watch commands

  • pitcrew context-watch status [--project DIR] prints the settings, the project's snapshot folder with its number of snapshots, and PitCrew's settings file. When the settings were read from PaceLine's file, a last line says settings read from <path> (from PaceLine). DIR defaults to the current directory.
  • pitcrew context-watch config [--on|--off] [--line on|off] [--levels 85,95] [--days N] shows or changes the settings. --off turns off the line, the warnings, and the snapshots. --line on adds the line to every prompt; --line off hides it, which is the default. Levels are ascending whole percents from 50 to 99. Snapshots are kept 1 to 90 days. It prints context-watch on · line off · warn at 85%, 95% of the auto-compact point · snapshots kept 14 days with the current values, and writes the settings only when an option is given. Changes apply from the next prompt.

Defaults: on, line off, warnings at 85% and 95%, snapshots kept 14 days.

Settings

context-watch has four settings and cache-watch two defaults. The table is read from the plugin's own constants. A stored value outside its range reads as the default, each setting on its own. The levels of context-watch must rise: each level is above the one before it, otherwise the list reads as the default.

WatcherKeyDefaultRange
context-watchontrueon or off
context-watchlinefalseon or off
context-watchlevels[85, 95]50–99
context-watchsnapshot_days141–90
cache-watchlead_minutes51–30
cache-watchmax_wakes51–20

PitCrew's settings files are context-watch.json and cache-watch.json in its state directory. They are read in this order, for each file on its own:

  1. The file in PitCrew's state directory, when it exists. It is then the only source; a field it lacks or holds out of range reads as the default.
  2. Else the file of the same name in PaceLine's state directory, which PaceLine 0.6.0 and earlier wrote.
  3. Else the defaults.

A config command always writes the whole settings object to PitCrew's state directory. PaceLine's files are never written, moved or deleted. pitcrew context-watch status names the file the settings were read from.

Skills

Each skill runs the matching command for you:

  • /pitcrew:context-watch status|config
  • /pitcrew:cache-watch on|off|status|config

Files and folders

<state> is PitCrew's state directory: $PITCREW_STATE_DIR when set, else <config>/state/pitcrew. <config> is $CLAUDE_CONFIG_DIR, else ~/.claude. <legacy> is PaceLine's: $PACELINE_STATE_DIR, else <config>/state/paceline.

PathWhat it holds
<state>/context-watch.jsoncontext-watch settings: on, line, levels, snapshot_days. PitCrew writes it when a config command changes a value.
<state>/cache-watch.jsonThe defaults of cache-watch, lead_minutes and max_wakes. A value outside its range reads as the default.
<legacy>/context-watch.jsonPaceLine's copy of the settings. Read only while <state>/context-watch.json does not exist; never written, moved or deleted.
<legacy>/cache-watch.jsonPaceLine's copy of the defaults, read under the same rule.
${CLAUDE_PLUGIN_DATA}/cache-watch/<session id>.jsoncache-watch state of one session. Not carried over from PaceLine's data directory.
<project>/.claude/pitcrew/<session id>.mdcontext-watch snapshots. The folder has its own .gitignore (*), so git ignores it. Snapshots older than the snapshot days are removed at session start.
<project>/.claude/paceline/*.mdSnapshots PaceLine wrote. PitCrew removes those older than the snapshot days at session start and touches nothing else in the folder.
<config>/projects/<project>/<session id>.jsonlThe session transcript, a private file of Claude Code. cache-watch reads it for the main thread's cache writes; it never writes it.

Environment variables

VariableWhat it does
CLAUDE_CONFIG_DIRClaude Code's configuration directory. PitCrew's state directory and PaceLine's are under it, and cache-watch looks for transcripts in its projects folder. Unset or empty: ~/.claude.
CLAUDE_PLUGIN_DATAThe plugin's data directory, set by Claude Code for hooks. cache-watch keeps each watched session's state there. The Bash tool does not have it, so the skill passes --data-dir.
CLAUDE_PROJECT_DIRThe project whose old snapshots are removed at session start. When it is not set, the cwd of the hook's input is used.
HOMEWhere the module finds the home directory to compute <config> when CLAUDE_CONFIG_DIR is not set and USERPROFILE is not set.
PACELINE_STATE_DIRPaceLine's state directory, which PitCrew reads settings from while it has none of its own. Unset or empty: <config>/state/paceline.
PITCREW_STATE_DIRPitCrew's state directory. Unset or empty: <config>/state/pitcrew.
USERPROFILEWhere the module finds the home directory to compute <config> when CLAUDE_CONFIG_DIR is not set; HOME is the fallback.

The module reads the variables from the environment Claude Code starts in. The table is checked against the variables PitCrew's code reads.

Exit codes

  • 0: success.
  • 1: a refused value, with the message on stderr as pitcrew context-watch: ... or pitcrew cache-watch: ..., for example levels must be ascending whole percents 50-99, e.g. 85,95, days must be 1-90, lead must be 1-30 minutes or max must be 1-20. A refused value changes nothing.
  • 2: an invalid command line, or pitcrew with no group or an unknown one.
  • 3: cache-watch on uses 3 for not started.

Hooks

HookWhenWhat it does
Module: UserPromptSubmit, PostToolBatch, session.compact, SessionStart after a compactionEvery prompt, tool batch, and compactioncontext-watch. Does nothing while context-watch is off, and never vetoes a compaction.
Stop: cache_watch.py hook stopAfter every turnWaits for the next wake of a watched session; returns at once for any other session. When the cache expired before the wake, turns the session off with the reason cache expired before the wake.
UserPromptSubmit: cache_watch.py hook promptEvery promptResets the wake count of a watched session. After a cache that expired before its wake, adds a one-time notice for the agent to pass on.
PreCompact, SessionStart (compact): cache_watch.py hook compactBefore and after a compaction, manual or automaticTurns a watched session off with the reason compacted, which also ends its waiting Stop hook.
SessionEnd: cache_watch.py hook session-endSession endRemoves the session's cache-watch state.
SessionStart: context_watch.py hook session-startSession startRemoves old snapshots while context-watch is on.

The command hooks run python3 when it works, else python. While a watcher is off, its command hooks still start one Python process per matching event. A cache-watch wake starts its prompt with pitcrew cache-watch woke this session; PaceLine recognises a wake by cache-watch woke this session, so a wake does not clear PaceLine's away marker.

Requirements

  • Claude Code 2.1.287 or later.
  • Python 3.9 or later on PATH as python3 or python, in the environment Claude Code starts in. PitCrew uses the standard library only.
  • cache-watch needs an interactive session whose main thread writes one-hour cache entries. See Limitations.
