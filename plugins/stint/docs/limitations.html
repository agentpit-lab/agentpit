Requirements and surfaces

Requirements: Claude Code 2.1.287 and Python 3.9

Stint needs Claude Code 2.1.287 or later and Python 3.9 or later on PATH as python3 or python.

without python3 and without python on PATH, stint does not run. Python older than 3.9 is not supported.

everything else in Claude Code. See Reference.

Where an organization manages Claude Code, Stint's module may not run

Stint's module uses only session.measure. That event is not among the ones that Claude Code's sec-default guard keeps from a module of a user-installed plugin (prompt, tool-batch, session-start and compaction), so the module should run. This is not verified on a machine where an organization manages Claude Code.

if the guard stops the module, limits.json is not written, and without PaceLine stint next waits with no usage reading yet.

the queue commands, and with PaceLine the advice, which does not use Stint's module.

The Windows power script needs elevation

scripts/night-power.ps1 sets the Windows Update active hours and the power plan, which needs an elevated PowerShell for -Enable and -Disable. It runs on Windows only.

without elevation the script stops with Active-hours changes need an elevated PowerShell session. Re-run as Administrator.

the dry run, which needs no elevation, and, on macOS and Linux, caffeinate and systemd-inhibit. See Keep the computer awake for the night.

Alongside PaceLine

PaceLine's leftover pool is gone and its items are not carried over

PaceLine 0.6.0 and earlier had a leftover pool (paceline queue --pool) that ran pre-approved items on the last night before the weekly reset. Stint has no pool: the last part of the week plan already takes what is left of the week, and the pool needs a fact only PaceLine knows. Stint does not read PaceLine's pool file.

stint list shows no L items from the pool, and there is no --pool option.

the ordinary queue and its items carry over. Queue the pool's items as ordinary items in the last night before the weekly reset. See Move from PaceLine's queue.

Two queue copies on a machine with an older PaceLine

PaceLine 0.6.0 and earlier keep their own queue (paceline queue and paceline auto) in state/paceline/night-queue.json. With such a PaceLine and Stint installed, there are two queue commands. Stint reads PaceLine's file until it writes its own queue.json; after its first write the two queues do not share state. Stint does not detect the other copy.

after Stint's first write, paceline queue list and stint list show different queues, and paceline auto and stint next decide on different ones.

each queue works on its own. Use one of them; a PaceLine that has dropped its queue ends the overlap. See Move from PaceLine's queue.

A run that PaceLine stored without an end ends at 09:00 UTC of its night date

A run stored by PaceLine 0.6.0 or earlier may carry a night_date and no night_end. Stint ends such a run at 09:00 UTC of that date, the default start of work. PaceLine used the time zone of its profile, which Stint does not read.

stint next says night ended at 09:00 UTC, not at your local start of work.

stint next --start-run opens a new run, with the end of tonight's part from PaceLine, or with none without PaceLine.

Without PaceLine

Without PaceLine a run has no end of its own

Without PaceLine there are no working hours to bound a night, so stint next --start-run stores a run with no end. The run closes at its first stop, when the queue is empty or the week stop is reached: stint next stores ended_at, and the next stint next --start-run opens a new run.

a queue that is left running goes on into the day until its first stop or an empty queue; night ended never appears.

the week stop and the five-hour stop, which apply at every stint next. See Run without PaceLine.

Several accounts without PaceLine read the latest reading of any session

limits.json holds the latest reading of any session on the machine. With two accounts on one machine, Stint without PaceLine may read the figures of the other account. PaceLine keeps the accounts apart.

the week and five-hour stops of stint next follow figures that may belong to another account.

with PaceLine, its advice names the account, and Stint stops the run when the account changes. With one account on the machine, nothing changes.

Without PaceLine, no open session means no usage reading

Stint reads the limits that Claude Code hands to a session. The module writes them only while a session measures its limits, and a reading older than 30 minutes is stale.

stint next waits with no usage reading yet or usage data stale (<n> min).

the queue commands, and the run resumes as soon as a session writes a fresh reading. See The queue waits with no usage reading.

Without PaceLine there are no model-scoped limits

stint next names no model. With PaceLine, /stint:run reads each model's own weekly limit from paceline status --json. Without PaceLine no such figures exist, so the agent chooses a model by the item's needs.

an item may run on a model whose own weekly limit is spent, and fail.

the week and five-hour stops. Defer an item with stint defer when it needs a model that is out of limit.

The queue

PaceLine hold calls run under the queue lock

stint start, stint done, stint defer and stint fail at the third attempt call PaceLine while they hold queue.lock. A PaceLine call can take up to 60 seconds before Stint gives up, and a second Stint command waits for the lock for 10 seconds only. A lock is taken over only when it is older than 300 seconds, so it is never taken from a command that still waits for PaceLine.

while one command waits for PaceLine, another fails with stint: queue is locked: <path>.

the failed command writes nothing, so it can be run again, and no update is lost: only the command that holds the lock deletes it. A skill runs the commands one after another. See A command fails with a locked queue.

A failed PaceLine hold does not stop the command

When PaceLine cannot take a hold at stint start, Stint prints stint: PaceLine hold not taken: <why> on stderr and starts the item anyway. A hold it cannot release is reported as PaceLine hold not released and stays on the item, so a later stint done or stint defer tries again; otherwise PaceLine's lease ends it after 240 minutes. The item's state change is kept either way.

an item that runs without a hold is not counted by PaceLine's advice, which may then offer more budget than is left.

the queue itself: stint done and stint defer still finish the item. paceline hold list shows the holds that exist.
