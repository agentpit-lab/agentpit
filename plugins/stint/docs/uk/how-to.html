Практичні інструкції Stint

Задачі зі Stint: для кожної зазначено, коли вона потрібна, кроки та як перевірити результат. Для кожної команди й параметра див. довідник; для того, чого Stint не вміє, див. обмеження.

Поставити роботу в чергу і запустити її

потрібно, щоб агент пройшов список задач, поки власника немає, у межах того, що тиждень може собі дозволити.

  1. Додати елементи, кожен з оцінкою у відсотках тижневого ліміту. У сесії це робить /stint:queue:

    stint add --title "Add the export command" --repo my-repo --estimate 2.5
stint add --title "Document it" --repo my-repo --estimate 1 --depends Q1

    Елементи отримують ID Q1, Q2 і так далі. --independent додають до елемента, який може виконуватися поруч з іншими незалежними елементами. --depends Q1,Q2 змушує елемент чекати на ці елементи; кожна залежність має вже існувати.

  2. Доручити агентові запустити чергу командою /stint:run. Він один раз починає прогін командою stint next --start-run, а далі перед кожним елементом запускає stint next --json і діє за кодом виходу:

    • 0 (start): запустити stint start <id> для елемента, названого у відповіді, виконати роботу, потім stint done <id>. Якщо перевірки елемента не проходять, запустити stint fail <id> і виправити їх; після 3 невдач елемент відкладається. Якщо елемент потребує дозволу власника, запустити stint defer <id>. Відкладення елемента відкладає й елементи, що від нього залежать.
    • 10 (wait): зачекати, потім знову запустити stint next. З --json поле wait_until каже, до якого часу; воно null, поки Stint чекає на елементи, що виконуються, залежності або перший показник використання.
    • 11 (stop): завершити прогін. reasons у JSON каже чому.

  3. Уранці агент заповнює шаблон звіту templates/morning-report.md з виводу stint report і стану черги та надає звіт у своїй відповіді.

Щоб змінити чергу між прогонами: stint retry <id> повертає елемент у стан pending і скидає лічильник невдач, stint remove <id> видаляє його (відмовляє, поки від нього залежить елемент у стані pending або running), а stint clear-done видаляє виконані елементи.

stint report виводить, наприклад, done 2 (est 5.00% act 4.10%), deferred 1, running 0, pending 0, а stint list показує стан кожного елемента, а для відкладеного ще й причину.

Спланувати сьогоднішню частку

використовується PaceLine, а stint add вивів рядок про те, що частка сьогоднішніх неробочих годин дорівнює 0, або stint next зупиняється з nothing can start before the night ends.

З PaceLine бюджет прогону — це те, що лишилося від частки поточної частини, а типова позначка неробочих годин дорівнює 0: без позначки частина не має частки, тож stint next чекає і, оскільки нічого не може стартувати до кінця ночі, зупиняється.

  1. Переглянути сьогоднішню частину. paceline plan показує частину ☾ як off і 0 %:

    paceline plan

  2. Позначити ніч до її початку або кожну понеділкову ніч шаблоном:

    paceline plan set today --off-hours 0.5
paceline plan template set mon --off-hours 0.5

    Позначка, встановлена, коли сьогоднішні неробочі години вже тривають, ділить частину в цю мить: решта ночі отримує частку від залишку тижня.

  3. Знову запустити stint next --json і прочитати budget_for_next_item_pct та reasons.

У /stint:queue агент одразу питає, чи виконувати команду з підказки, і виконує її лише після згоди.

paceline plan показує частину ☾ з позначеною часткою, а stint next відповідає start або чекає з причиною, що називає пізніший час, а не зупиняється.

Працювати без PaceLine

PaceLine не встановлено або STINT_PACELINE має значення off, а прогін потрібно обмежити власними лімітами Stint.

  1. Переглянути параметри та показник:

    stint config

    Команда виводить зупинку за тижнем (типово 85), зупинку за п'ятигодинним вікном (типово 95) і кількість агентів (типово 3), потім PaceLine: not found і вік показника використання. usage reading: none означає, що жодна сесія ще не передала ліміти.

  2. Змінити потрібне. Кожен параметр перевіряє свій діапазон і нічого не записує, коли значення відхилено:

    stint config --week-stop 80 --five-hour-stop 90 --agents 2

  3. Тримати відкритою сесію на комп'ютері. Модуль Stint записує ліміти, які Claude Code показує в рядку стану, у limits.json, коли сесія їх вимірює; показник старший за 30 хвилин змушує stint next чекати.

  4. Почати прогін командою /stint:run. Поле source відповіді має значення stint, а limits містить показники тижня та п'ятигодинного вікна з їхніми зупинками.

Прогін закривається на першій зупинці, коли черга порожня або досягнуто зупинки за тижнем; без PaceLine він не має власного кінця. Наступної ночі новий прогін відкривається командою stint next --start-run. Зупинка за п'ятигодинним вікном лише змушує чекати, доки вікно не скинеться.

За показника тижня 86% stint next виводить next: STOP | week 86% >= 85% stop; за 40% тижня і 96% п'ятигодинного вікна він виводить next: WAIT until <reset> | 5h window 96% >= 95% stop, resets <reset>.

Не давати комп'ютеру заснути на ніч

черга залишається працювати на ніч, а комп'ютер інакше заснув би або перезапустився для оновлення.

  1. У Windows scripts/night-power.ps1 у каталозі плагіна вимикає сон від мережі живлення і переносить активні години Windows Update на ніч. Без перемикача скрипт працює в пробному режимі й виводить, що саме змінив би. Спершу запустити його так:

    pwsh -File "<plugin directory>/scripts/night-power.ps1"

  2. Перед ніччю запустити його з -Enable, а після неї з -Disable, обидва рази в PowerShell з правами адміністратора. Попередні значення зберігаються в <state>/night-power-state.json. -NightStart і -NightEnd задають години (типово 0 і 8); передати години, що відповідають ночі, наприклад:

    pwsh -File "<plugin directory>/scripts/night-power.ps1" -Enable -NightStart 18 -NightEnd 9

  3. У macOS запустити сесію під caffeinate -i -s, наприклад caffeinate -i -s claude. У Linux запустити її під systemd-inhibit --what=sleep, наприклад systemd-inhibit --what=sleep claude.

-Disable відновлює значення, збережені -Enable. Коли файлу стану Stint немає, він читає night-power-state.json, який записала копія скрипта в PaceLine. Агентові не давати запускати -Enable чи -Disable: вони змінюють системні налаштування, тож запускати їх самостійно.

Пробний запуск називає файл стану Stint і поточні значення; після -Enable схема живлення не показує сну від мережі, а після -Disable збережені значення повернено.

Перейти з черги PaceLine

використовувалися paceline queue і paceline auto (PaceLine 0.6.0 і раніші), а тепер встановлюється Stint.

  1. Встановити Stint. Доки він не запише власний queue.json, він читає чергу, яку PaceLine вів у state/paceline/night-queue.json, тож елементи та їхні ID переходять. Файл PaceLine ніколи не записується, не переміщується і не видаляється. Коли його не вдається прочитати, Stint виводить stint: PaceLine's queue <path> cannot be read (<why>); starting from an empty queue і починає з порожньої черги.

  2. Перевірити елементи:

    stint list

    Перша команда, що записує, створює queue.json. Відтоді працювати лише командами stint: paceline queue більше не бачить того, що змінює Stint.

  3. Використовувати /stint:run там, де використовувався skill нічної черги, і stint next там, де запускався paceline auto. Коди виходу ті самі: 0 start, 10 wait, 11 stop.

Пул залишкових задач (paceline queue --pool) не переноситься. Такі елементи ставлять у чергу як звичайні в останню ніч перед тижневим скиданням. PaceLine, що позбувся черги, відповідає на paceline queue і paceline auto одним рядком із назвою Stint і завершується з кодом 2.

stint list показує елементи, поставлені в чергу під PaceLine, а новий stint add отримує наступний ID після найбільшого.
