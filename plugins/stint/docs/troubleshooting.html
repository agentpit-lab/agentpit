Stint troubleshooting

What a symptom means and what to do about it. Every answer of stint next carries reasons in its JSON; start there. For every command and setting, see the reference; for what Stint cannot do, see the limitations.

Symptoms

  • The queue stops at once
  • The queue waits with no usage reading
  • The queue waits for an item that is stuck running
  • PaceLine is not found
  • The hint for tonight's share is not shown
  • A command fails with a locked queue

The queue stops at once

stint next exits 11 (stop) before any item starts. The last part of its line says why:

  • no run: start one with stint next --start-run: no run is open, or the last one closed at its first stop. --start-run opens one.
  • night ended: the run's end is reached. A run stored by PaceLine without an end ends at 09:00 UTC of its night date.
  • week <w>% >= <s>% stop: without PaceLine, the week is at its stop.
  • queue empty, or all remaining items need owner permission when only deferred items are left.
  • budget exhausted: no item fits <budget>%: every pending item is larger than the budget.
  • account changed during the run, with PaceLine: the account of the advice differs from the run's.
  • With PaceLine, the advice's own reasons: a safety stop (memory, weekly, weekly_scoped), or a part with no share together with nothing can start before the night ends.

Read the answer in full:

stint next --json

reasons holds the texts, source says whose limits decided (paceline or stint), run shows the run's start, ended_at and end, and limits holds the figures Stint's own stops used.

Per reason: open a run with stint next --start-run; for night ended, open a new run the same way; for a week stop, wait for the reset or raise the stop with stint config --week-stop; for a share of 0, mark the night as in Plan tonight's share; for a budget that fits no item, split the item or estimate it lower; for a changed account, open a new run.

The queue waits with no usage reading

stint next keeps exiting 10 (wait) with no usage reading yet or usage data stale (<n> min). Without PaceLine, Stint reads the limits that Claude Code hands to a session, and nothing wrote a fresh reading:

  • No session has run since Stint was installed. The module loads at session start.
  • No session is open, or none has measured its limits for over 30 minutes.
  • Where an organization manages Claude Code, the module may not run (see Limitations).

Look at the age of the reading:

stint config

usage reading: none means limits.json does not exist or holds no window; a number is the age in minutes. The file is <state>/limits.json.

Start a new session after installing Stint, and keep a session open while the queue runs; the run resumes at the next stint next after a session writes a reading. To bound the run without a reading, install PaceLine.

The queue waits for an item that is stuck running

stint next keeps exiting 10 with waiting for running items or dependencies. An item was started and never marked done, failed or deferred, for example because its session was cut off. An item that is not independent never runs beside another, so the queue waits for it.

List the items:

stint list

An item in [running] that no session is working on is stuck.

Finish it with stint done <id>, count a failed attempt with stint fail <id>, or defer it with stint defer <id>. Each releases the item's PaceLine hold. stint retry <id> puts a deferred item back to pending.

PaceLine is not found

PaceLine is installed, but stint config prints PaceLine: not found, or stint next answers with source stint and a last reason that starts with PaceLine's advice unavailable (:

  • paceline is not on the PATH of the shell that runs Stint.
  • STINT_PACELINE is off, or names a program that does not exist, or a .cmd or .bat launcher with no scripts/paceline.py beside its folder.
  • paceline advice --json gave no usable answer: no output, a timeout after 60 seconds, or an advice_version other than 1. The text in brackets says which.

Check what Stint found and run the call yourself:

stint config
paceline advice --json

stint config names the program it will call.

Put paceline on the PATH, or set STINT_PACELINE to the program's path (a path ending in .py runs with the current Python) and unset it when it is off. For an unusable advice, update PaceLine so that its advice has advice_version 1. Meanwhile Stint's own stops apply, so the run is bound, though not by the week plan.

The hint for tonight's share is not shown

stint add prints no second line, although the queue does not run tonight. The hint appears only when PaceLine is found, paceline status --json answers, tonight has an off-hours mark and that mark's weight is 0:

  • PaceLine is not found, or its status call failed. Without PaceLine there is no plan and no hint.
  • night.mark is null: tonight carries no mark, so the hint is not printed.
  • The share is not 0, so the queue can run.
  • The item was added with --json: the line is the value of tonight_off_hint.

Add an item with --json and read the two keys, then look at tonight in PaceLine's status:

stint add --title test --repo r --estimate 1 --json
paceline status --json

tonight_off_share_pct is the share and tonight_off_hint the line, or null; the night object of the status has mark, weight and share_pct.

Find PaceLine as in PaceLine is not found. With no mark, run paceline plan and mark the night as in Plan tonight's share. Under /stint:queue, the agent asks you at once whether to run the command of the hint.

A command fails with a locked queue

A stint command exits 2 with stint: queue is locked: <path>. Another stint command holds queue.lock, for example while it waits for PaceLine, or a command that was killed left the file behind. A writer waits up to 10 seconds, and a lock older than 300 seconds is taken over.

The path in the message is the lock file. Check whether a stint process is still running and how old the file is.

Run the command again after a moment. When no stint process runs, the lock is taken over after 300 seconds; deleting queue.lock earlier is safe only when no stint command is running.
