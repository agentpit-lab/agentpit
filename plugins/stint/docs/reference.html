Stint reference

Every command, setting, file, environment variable, exit code and JSON key of Stint, and the order in which stint next decides. For tasks, see the how-to guides; for what it cannot do, see the limitations.

Commands

stint runs in the session's Bash tool, where Stint puts it on the PATH; the skills run it for you. Every command takes --json to print its payload instead of one text line. If stint is not found, run python "${CLAUDE_PLUGIN_ROOT}/scripts/stint.py" with the same arguments. The table is read from the plugin's own command parser.

CommandWhat it does

stint listList the items.
stint reportCount the items finished since the run started, and those running or pending.
stint startStart a pending item (takes a PaceLine hold when PaceLine is found).
stint doneFinish an item (releases its hold).
stint failCount a failed attempt; the third defers the item and its dependents.
stint deferDefer an item and every item that depends on it.
stint retryPut an item back to pending.
stint removeRemove an item.
stint clear-doneRemove the done items.
stint configShow the settings, or change them.
stint nextAnswer start, wait or stop for the next item (exit 0, 10 or 11).

Queue commands

  • add --title TEXT --repo NAME --estimate PCT [--independent] [--depends ID,ID] queues an item with the next id Q<n>. --independent lets it run beside other independent items. Every dependency must already exist. With PaceLine, add also prints the hint for tonight's share of 0 (see Tonight's share).
  • list lists the items with their status, estimate, dependencies and, for a deferred item, its reason. report counts the items finished since the current run started (all items when there is no run) and the running and pending ones, with the sums of the done items' estimates and actual costs.
  • start ID [--pid N] turns a pending item into a running one and records when it started and the week's usage then. With PaceLine it also takes a queue hold with the key stint-<id>, which PaceLine keeps for 240 minutes. An item that is not pending is refused.
  • done ID [--actual PCT] marks the item done and releases its hold; a hold that cannot be released stays on the item. The actual cost defaults to the week's usage now minus the usage at start, not below 0; it stays unknown when either is unknown.
  • fail ID [--reason TEXT] counts one failed attempt. At the third, the item is deferred, with the reason gates failed after 3 fix attempts unless --reason gives one.
  • defer ID [--reason TEXT] defers the item and, transitively, every pending or running item that depends on it, and releases their holds. An item that is not pending or running is refused: stint: <id> is <status>, not pending or running. The default reason is needs owner permission; the dependents get depends on deferred <id>.
  • retry ID puts an item back to pending and resets its failure count. remove ID deletes an item; it is refused while a pending or running item depends on it. clear-done deletes the done items.

An item is pending, running, done or deferred. Ids match case-insensitively.

stint next

next [--start-run] answers whether the next item may start. It exits 0 for start, 10 for wait and 11 for stop, and prints one line:

  • next: START <id> | budget <b>% | agents <=<n>, with the reasons appended after | when there are any;
  • next: WAIT until <time> | <reasons>, or next: WAIT | <reasons> when no time is known;
  • next: STOP | <reasons>. Reasons are joined by ; .

--start-run opens a run unless one is open: a run is open until it has ended_at, while its end is null or later than now and, with PaceLine, the account is the same. next closes the open run at the first stop it answers: the run gets ended_at, counts as no run from then on, and the next --start-run opens a new one. Then that run is kept and the answer has reused true. A new run archives the old one (the last 14 are kept) and stores the start, the end, the account, the source, the budget at that moment and the week's usage. With PaceLine the end is night.end of paceline status --json, the end of tonight's off-hours part; without PaceLine it is null.

stint config

config [--week-stop PCT] [--five-hour-stop PCT] [--agents N] shows the three settings, each with its default, whether PaceLine was found and which program, and the age of the usage reading. With an option it first writes the value. A value out of range or not a whole number is an error and nothing is written.

Settings

Stint has three settings, which it applies when PaceLine does not decide. The table is read from the plugin's own constants. They live in <state>/settings.json, and each field falls back to its default on its own when the file lacks it or holds an invalid value.

KeyOption of stint configDefaultRange
week_stop_pct--week-stop8550–100
five_hour_stop_pct--five-hour-stop9550–100
agents--agents31–6
  • week_stop_pct: at or above this share of the week, the run stops.
  • five_hour_stop_pct: at or above this share of the five-hour window, the run waits until it resets.
  • agents: the number of parallel agents stint next allows when it starts an item without PaceLine.

With PaceLine, the budget and the agents come from PaceLine's advice, and the settings apply only when its advice is unavailable.

Skills

Two skills run the commands in a session:

  • /stint:queue adds, lists and changes items and asks you before running the command of the tonight's-share hint.
  • /stint:run works the queue: it starts the run, loops over stint next, and fills the morning report from templates/morning-report.md. It chooses the model of each item itself; with PaceLine it reads the model-scoped weekly buckets from paceline status --json, without it no scoped figures exist.

How next decides with PaceLine

Stint runs paceline advice --json. The advice is valid when the output is a JSON object with advice_version 1, an action of start, wait or stop and a list of reasons, whatever the exit code. Anything else (no output, a timeout, another version) makes the advice invalid: Stint's own order applies, source is stint, and the reasons end with PaceLine's advice unavailable (<why>): Stint's own stops apply. With a valid advice, the first match wins:

  1. No run, or a run that has ended_at: stop, no run: start one with stint next --start-run.
  2. The run's account and the advice's are both known and differ: stop, account changed during the run.
  3. The run's end is reached: stop, night ended.
  4. An advice reason has the effect stop and the code memory, weekly or weekly_scoped: stop, with the advice's reason texts.
  5. The run's account is known and the advice's is null: wait, account unknown.
  6. The queue is empty: stop, queue empty. Only deferred items are left: stop, all remaining items need owner permission.
  7. The advice says stop: stop, with the advice's reason texts.
  8. The advice says wait: when its wait_until is null or before the run's end (or the end is null), wait until the advice's wait_until, with its texts; otherwise stop, with its texts and nothing can start before the night ends.
  9. No pending item fits the budget: stop, budget exhausted: no item fits <budget>%. Items are running or dependencies unfinished: wait, waiting for running items or dependencies.
  10. Otherwise start the item. The budget is the advice's budget_pct, the agents are its agents, and the reasons are the texts of its limit reasons.

How next decides without PaceLine

Without PaceLine, or with an invalid advice, the first match wins. Percentages in the texts are whole numbers.

  1. No run, or a run that has ended_at: stop, no run: start one with stint next --start-run.
  2. The run's end is reached: stop, night ended.
  3. No reading, or one without the week bucket (seven_day): wait, no usage reading yet: Stint reads the limits Claude Code hands to a session. A reading older than 30 minutes: wait, usage data stale (<n> min).
  4. The week is at or above week_stop_pct: stop, week <w>% >= <s>% stop.
  5. The queue is empty or only deferred items are left: stop, as in step 6 with PaceLine.
  6. The five-hour window is at or above five_hour_stop_pct: wait until its reset, 5h window <u>% >= <s>% stop, resets <time> (resets later when no reset time is known).
  7. The item rules with the budget week_stop_pct minus the week's usage, not below 0: as in step 9 with PaceLine.
  8. Otherwise start the item, with agents agents and no reasons.

A bucket whose reset time has passed reads as 0%. A reading is stale when it is more than 30 minutes old.

Item rules

Both orders choose the item the same way. The next item is the first pending one whose dependencies are done and whose estimate fits the budget. An item that is not independent never runs beside another item, and no item runs beside it. When there is no such item, the rule gives one of four results:

  • empty: no items are left to run.
  • blocked: only deferred dependencies or deferred items are left.
  • waiting: items are running or dependencies are unfinished.
  • budget: pending items remain but none fits the budget.

The JSON of next has these keys:

  • action (start, wait or stop), may_start_next_item and max_parallel_agents (0 unless start).
  • budget_for_next_item_pct: the advice's budget_pct with PaceLine, Stint's own budget otherwise, 0 when there is no run.
  • next_item: the item's id, title, repo, estimate_pct, independent, depends_on, status, reason, attempts and actual_pct; null unless start.
  • wait_until (only on wait, else null) and reasons (strings).
  • run: started_at, ended_at (null while the run is open), end, source, allowance_pct (the budget when the run started, informational), spent_pct (the week's usage now minus the usage at start, not below 0, null when unknown) and reused; null when there is no run.

  • limits, when Stint's own stops decide: week_pct, five_hour_pct, five_hour_resets_at, age_min, week_stop_pct and five_hour_stop_pct, null where unknown; null with PaceLine.

Files and folders

<state> is Stint's state directory: $STINT_STATE_DIR when set, else <config>/state/stint. <config> is $CLAUDE_CONFIG_DIR, else ~/.claude. <legacy> is PaceLine's: $PACELINE_STATE_DIR, else <config>/state/paceline.

PathWhat it holds
<state>/queue.jsonThe queue: run, past_runs, next_id and items. Written whole, as UTF-8 with LF, by an atomic replace, under queue.lock. An unreadable file or one that is not a JSON object is an error that names the file, and so is an items entry that is not an object; the file is never overwritten.
<state>/queue.lockThe lock of the queue, created exclusively; it holds a token of its own, and only the command with that token deletes it. A writer waits up to 10 seconds; a lock older than 300 seconds is taken over.
<state>/settings.jsonThe settings week_stop_pct, five_hour_stop_pct and agents. Written by stint config.
<state>/limits.jsonThe last usage reading: observed_at, session_id and the buckets five_hour and seven_day, each with used_percentage and resets_at. Written by the module of the plugin, when the figures changed or a minute passed since the last write.
<legacy>/night-queue.jsonPaceLine's queue. Read only while <state>/queue.json does not exist; never written, moved or deleted. A run in it may carry night_end, which Stint reads as the run's end. A file that cannot be read or is not a JSON object gives one line on stderr, stint: PaceLine's queue <path> cannot be read (<why>); starting from an empty queue, and an empty queue.
<state>/night-power-state.jsonThe power settings that night-power.ps1 -Enable saved, restored by -Disable.
<legacy>/night-power-state.jsonThe file PaceLine's copy of the script wrote. -Disable reads it only when Stint's file is absent.

PaceLine's leftover pool file is not read.

Environment variables

VariableWhat it does

A path: the program to call (a path ending in .py runs with the current Python; one ending in .cmd or .bat is never run: Stint runs the scripts/paceline.py beside the launcher's folder with the current Python, and counts PaceLine as not found when that file is missing). The module reads the variables from the environment Claude Code starts in; the scripts read them from the environment of the command. Stint's calls into PaceLine run in the caller's environment. night-power.ps1 reads STINT_STATE_DIR, CLAUDE_CONFIG_DIR and PACELINE_STATE_DIR too. The table is checked against the variables Stint's code reads.

Exit codes

  • 0: success; for next, start. A failed PaceLine hold call keeps 0 and prints stint: PaceLine hold not taken: <why> or stint: PaceLine hold not released: <why> on stderr.
  • 10: next says wait.
  • 11: next says stop.
  • 2: an invalid command line or input, with the message on stderr as stint: ..., for example stint: unknown dependencies: Q9, stint: no item Q9, stint: Q1 is done, not pending, stint: Q1 has dependents Q2; defer or remove them first, stint: week_stop_pct must be 50-100, or a queue file that cannot be read or locked.

Module

Stint has no command hooks. Its hooks/hooks.json loads one module, hooks/register.tsx, which handles one event:

  • session.measure: writes the limits Claude Code hands to plugins (the figures of the status line) to <state>/limits.json, when the figures changed or a minute passed since the last write. A failed write is swallowed and never changes the step. It writes whether or not PaceLine is installed.

Requirements

  • Claude Code 2.1.287 or later.
  • Python 3.9 or later on PATH as python3 or python. Stint uses the standard library only.
  • Optional: PaceLine, for the advice. See Limitations.
