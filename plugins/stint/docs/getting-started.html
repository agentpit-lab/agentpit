Getting started with Stint

Stint keeps a queue of unattended work for Claude Code. You queue items, leave, and /stint:run works them one at a time; before each item, stint next answers start, wait or stop.

TL;DRInstall the plugin, queue an item with stint add, and run /stint:run before you leave. With PaceLine installed, PaceLine's advice decides; without it, Stint stops at 85% of the week and 95% of the five-hour window.

Install

  1. Install the plugin

    /plugin install stint@agentpit

    Stint needs Claude Code 2.1.287 or later, and Python 3.9 or later on PATH as python3 or python. The install adds the stint command, which is on the PATH of the agent's Bash tool, and the skills /stint:queue and /stint:run.

  2. Start a new session

    The module that records the limits Claude Code shows loads at session start, so a session that was already running when you installed Stint has written no reading yet. Skills that an update adds also need a new session in Claude Code Desktop.

  3. Check it

    stint config

    It prints the three settings with their defaults, whether PaceLine was found and which program, and the age of the last usage reading.

What Stint does

A queue item is a task with a repository and an estimate in percent of the week's limit. stint next looks at the queue and at the limits and prints one line with an exit code that the agent obeys:

  • 0, start: the line names the item, the budget for it and the number of agents, for example next: START Q1 | budget 5.00% | agents <=3.
  • 10, wait: nothing may start yet. The line says why and, when it is known, until when.
  • 11, stop: the run ends and closes. The line says why.

/stint:run is the skill that loops over this answer: stint start, the work, stint done or stint fail, then stint next again, and a morning report at the end. /stint:queue adds and changes items.

Items run in the order queued. An item waits for the items it --depends on, and an item that is not --independent never runs beside another item.

With PaceLine

When PaceLine is installed, Stint obeys paceline advice:

  • the budget for the next item, the number of agents, the waits and the safety stops come from PaceLine's week plan;
  • every item that runs is a queue hold in PaceLine's registry, so PaceLine's advice counts it;
  • the run ends when tonight's off-hours part of the plan ends.

Stint finds paceline on the PATH. STINT_PACELINE names another program, or, set to off, makes Stint ignore PaceLine.

Without PaceLine

Stint stops at its own limits, which it reads from the figures Claude Code shows in the status line:

  • at or above 85% of the week (stint config --week-stop), the run stops;
  • at or above 95% of the five-hour window (--five-hour-stop), the run waits until the window resets;
  • while there is no reading, or the last one is over 30 minutes old, no item starts.

A module of the plugin writes the reading to state/stint/limits.json whenever a session measures its limits, so a session must be open on the machine. The budget for an item is what is left of the week up to the stop. A run has no end of its own: it closes at its first stop, when the queue is empty or a stop is reached, and the next night opens a new run with stint next --start-run.

Tonight's share, with PaceLine

PaceLine plans the week in parts, and the default off-hours mark is 0: with no mark for tonight, the part has no share and the queue does not run. When you add an item and tonight's off-hours share is 0, stint add prints a second line with the command that plans some:

paceline plan set <date> --off-hours 0.5

Under /stint:queue, the agent asks you at once whether to run it and runs it only on your yes. Without PaceLine there is no plan and no hint.
