PitBoard how-to guides

Task guides for PitBoard. Each guide says when you need it, the steps, and how to tell it worked. For the meaning of each reading, see the reference.

Use PitBoard with PaceLine

you run several sessions and want an idle one to show the limits another session saw, you want Pace from the first draw of a new session, or you want the model-scoped weekly limits on the row.

PitBoard alone shows the five-hour and weekly limits of its own session, as Claude Code reports them after each model request. PaceLine records the readings of every session in its limits file, rate-limits.json, and keeps a history of them. PitBoard reads that file when it exists; it needs no setting for it.

  1. Install paceline:

    /plugin install paceline@agentpit

  2. Start a new session.

  3. To show the model-scoped weekly limits too, turn on PaceLine's usage-watch:

    /paceline:usage-watch on

    usage-watch is off until you turn it on. While it is on, PaceLine reads the account's usage, the figures /usage shows, every 125 seconds, and merges them with the model-scoped limits into the limits file.

  • A session you are not using shows a limit reading another session saw, within about 20 seconds of PaceLine writing it to the file.
  • Pace in the 5h limit and Week cards shows a rate from the first draw of a new session, when the file's history holds a reading of the current window at least 10 minutes old for the five-hour limit, or at least an hour old for the week.
  • With usage-watch on, each model-scoped limit appears in the limits group under its model's name, such as Fable, after the next usage-watch reading. If it does not, see A model-scoped limit disappears.
  • When PaceLine's pace is on and the five-hour window would reach PaceLine's threshold before the reset, the 5h limit card shows a Threshold row with the threshold and the clock time, for example 80% at 19:40, instead of Runs out, and the limit turns red. Without a fresh burn file, the card projects to 100% and shows Runs out.

Move the state directory

you keep PaceLine's files somewhere other than <config>/state/paceline, for example for a second, isolated setup. <config> is $CLAUDE_CONFIG_DIR, else ~/.claude.

PitBoard finds the limits file by PaceLine's own rule: $PACELINE_STATE_DIR/rate-limits.json when the variable is set and not empty, else <config>/state/paceline/rate-limits.json. PitBoard reads the variable from the environment Claude Code starts in.

  1. Set PACELINE_STATE_DIR in the environment that starts Claude Code: the shell you run claude from, or your user environment for Claude Code Desktop.

  2. Start a new session.

rate-limits.json appears in the new directory once PaceLine records a reading, and an idle session shows limits other sessions saw. If only one of the two plugins sees the variable, they look in different directories.

Use two accounts on one machine

you sign in to more than one Claude account on this computer and want the row to show the limits of the account you use now.

  • Without PaceLine, the row shows the limits of its own session. After a /login, the next reply brings the new account's figures.
  • With PaceLine, the row follows the signed-in account within about 20 seconds. Pace starts again from the new account's readings, because PitBoard drops the old account's samples. For the turn after the /login, the session's own figures may still be the old account's.
  • Account unknown on the 5h limit, Week, or a model-scoped card means that a figure comes from PaceLine's limits file and PitBoard cannot tell the file's readings to be the signed-in account's. See the reference for the row, and PaceLine's Status says account unknown for the reasons and the fix.

  1. Update both plugins together with /plugin marketplace update agentpit, and restart every open session. PitBoard 0.1.7 reads only the top level of the limits file, which is the account that wrote last.

  2. Run /login and sign in to the other account.

  3. Wait about 20 seconds. The row shows the new account's limits.

the cards show no Account row, and Pace fills in again after the first readings of the new account.

To keep the two accounts apart altogether, give each its own configuration directory. See Move the state directory and PaceLine's Use two accounts on one machine.

Read the row in Desktop

you use Claude Code Desktop and want to know what each mark on the row means.

The row sits above the prompt. Context and cache are pies the size of Desktop's own context ring. The five-hour and weekly limits are bars. Each model-scoped limit is a pie. The advisor has its own group between the context and the cache while an advisor is set. ⓘ ends the row.

  1. Point at a reading. PitBoard shades it and shows its card: the reading's name, one row per value, a bar for a limit, and advice when the reading needs a decision. While the pitboard pane is open, the row shows no cards, since the pane holds every one; the shading stays.

  2. Read a limit's bar. The fill is the share used. The tick marks where an even pace to the reset would stand now, which is the share of the window gone. A fill past the tick spends faster than the window allows.

  3. Read the colours: grey needs nothing, amber is worth a glance, red changes what to do next. See Levels for the thresholds.

  4. For the explanations behind a card, click pitboard in the footer under the prompt, between the mode and the model name, or run /pitboard; see Open every card with /pitboard.

The bars change with the window's width. PitBoard keeps the row on one line where it can:

  • In a wide window, 5h and 7d show a bar, the percentage, and the time to reset.
  • When that does not fit, the bars drop the time to reset first. The card still shows it.
  • When even that does not fit, 5h and 7d turn into pies, and show their numbers only once they leave calm.

a card appears when you point at a reading and goes when you move away. If a card stays up, see A Desktop card stays open.

Read the row in a narrow terminal

your terminal is too narrow for the whole row.

In the CLI the row sits under the prompt, below Claude Code's own mode and hint line, with a short rule above it. Each reading is its name and a two-cell gauge. A number appears only once the reading leaves calm, which keeps the row short while nothing needs you.

  1. Let the row wrap. It breaks between groups: context, cache, limits, and ⓘ with pitboard. A group stays whole.

  2. To read one reading's values, click its name, or press Enter while the name has focus. Its card opens as one line under the row, with ▲ under the name. The ⓘ card takes a second line from Claude Code on.

  3. A detail line that is wider than the terminal is cut at its end. To read every value, click pitboard at the end of the row, or run /pitboard.

the groups stack on separate lines, and a click on a name opens its line. A second click on the same name closes it.

Open every card with /pitboard

you want every reading with its explanation at once, a card cut short in a narrow terminal, or the readings in the Claude mobile app, which has no row.

  1. Run:

    /pitboard

    Or click pitboard: in the CLI the bracketed [ pitboard ] at the end of the row, beside ⓘ; in Desktop in the footer under the prompt, between the mode and the model name. The mobile app has the command only.

  2. Read the pane, titled pitboard, from the top:

    • Needs attention, only while something needs a decision: each warning with its advice, the most urgent first.
    • Every card in the row's order, with all its rows and its explanations. The advisor's card follows the context's while an advisor is set; the session card comes last.
    • Under 5h limit and Week, a bar with the used share and the even-pace tick. The 5h limit bar also shows, paler, where the current pace leads by the reset.

  3. Click pitboard again to close the pane, or use its close mark or Escape. If another pane is in front of it, the click brings it to the front first; in a terminal narrower than 110 columns that can take a second click.

the pane shows the cards; after /pitboard, Claude Code also answers pitboard pane opened.

The getting-started page draws the pane in the CLI and in Desktop: see Getting started, step 3.

Seat PitBoard as your organization's plugin

your organization manages Claude Code (a Team or Enterprise login, or a machine with managed settings) and PitBoard sees a compaction late: see the limitation. Claude Code's sec-default guard skips the hooks of a plugin you install yourself, but not of a plugin the organization's managed settings load from an administrator-only folder. Seating it there relaxes the organization's security settings, so it fits a small team whose owner decides that, and hardly a large organization.

One script per platform seats PaceLine and PitBoard together. It fetches each plugin from the public agentpit repository at its release tag, copies it into an administrator-only folder, writes a managed settings file that enables it there, and disables your own copies, paceline@agentpit and pitboard@agentpit. It never edits an existing managed-settings.json. dbWise needs none of this: the guard leaves its hooks alone.

  1. Where the organization has server-managed settings (claude.ai, Organization settings > Claude Code > Managed settings), add "managedSourcesBehavior": "merge" there. Without it Claude Code ignores the plugin keys of this machine's managed file, and with your own copies disabled neither plugin loads.

  2. On Windows, download Install-AgentpitOrg.ps1 and run it in PowerShell 7 as an administrator:

    pwsh -NoProfile -File .\Install-AgentpitOrg.ps1

  3. On macOS or Linux, download install-agentpit-org.sh and run it as yourself; it calls sudo where it writes system folders. It is tested on Windows and Linux, not yet on macOS.

    sh install-agentpit-org.sh

    In a terminal the script lists the last ten releases of each plugin with the latest selected, and Enter keeps it. -Version pitboard=0.1.14 (--version in sh) pins a release; -Latest (--latest) takes the latest of both without asking, as a run without a terminal does. Unreleased builds install only from a local folder with -Source (--source).

    The script writes two paths. Windows: C:\Program Files\ClaudeCode\plugins\agentpit-org and C:\Program Files\ClaudeCode\managed-settings.d\50-agentpit-org.json. macOS: the same two under /Library/Application Support/ClaudeCode/. Linux: /opt/claude-code/plugins/agentpit-org and /etc/claude-code/managed-settings.d/50-agentpit-org.json.

  4. Restart every Claude Code session.

claude --debug logs hooks module pitboard@agentpit-org loaded with tier append, and no line says bypassed by. claude plugin list does not show a plugin loaded in place from a managed folder.

To update, run the script again. To undo, run it with -Uninstall (--uninstall): it removes the folder and the managed file and enables your own copies again. The managed file applies to every login on the machine, a personal one included, and seats the guard there too: another plugin with a hooks module that you install from a marketplace loses the same events on that login.
