The row

The row has three groups of readings, context, cache, and limits, parted by │ in the CLI and by a thin rule in Desktop. Readings of one group are parted by a dot. ⓘ closes the row; in the CLI a pitboard button follows it.

A CLI gauge is two cells of a block that rises in eighths over a grey track, in the level's colour once the reading leaves calm. A Desktop pie or bar fills in the same colours.

In the CLI, a click on a reading's name, or Enter while the name has focus, opens its card as one line under the row, with ▲ under the opened name and a line of advice when the reading needs a decision. A second click closes it. In Desktop, pointing at a reading shades it and shows its card.

  • Context: Auto-compact reads on or off. When a smaller compaction window is set, it adds who set it: env, settings, account, experiment, model default, or default. Used counts toward the compaction point while auto-compact is on, and toward the full window while it is off. Left shows only while the compaction point is below the full window. Window shows only while auto-compact is on, as <compaction window> of <model window> when the two differ. The compaction point is read again as soon as /autocompact, /model or /config finishes. Turns left shows while auto-compact is on, once the context has grown over at least two of the last turns.
  • Cache: Countdown reads whole minutes while calm, mm:ss once it warns, replying while a reply runs, and expired after the cache has expired. TTL reads 1h or 5m, or 5m? until a cache write has shown which; in a new session that takes a few seconds after the first reply. If cold is the context the next turn writes again, and how many times dearer that turn is than a warm one for the session's model, such as ~40×; ≥20× marks a model whose cache-read price PitBoard does not know, so the ratio is a lower bound.
  • Cache hits: both rows are cache reads divided by reads plus writes. Session counts from the last compaction.
  • 5h limit, Week and a model-scoped limit: Account shows only as unknown, when a figure of the limit comes from the limits file and the file cannot be told to be the signed-in account's: the account could not be resolved, or the figures come from readings with no account. Figures from the session's own reply are never marked.
  • 5h limit: At reset gives the projected percentage at the reset. Runs out replaces it with the clock time the limit reaches 100% when that comes before the reset. With PaceLine's projection, Threshold takes the place of Runs out: it gives the threshold and the clock time the limit reaches it, for example 80% at 19:40 (the threshold is 80% by day and 95% at night by default), and Budget is the pace that reaches that threshold at the reset. See Budget, At reset, Runs out.
  • Week: Spare or Overspent gives the distance from even pace in points and in hours of budget.
  • ⓘ: Branch shows only when the branch could be read; see The Branch row is missing. API cost is the session at API prices; a subscription is not charged per token.
  • A row reads n/a while its number is unknown, for example Pace before it has enough readings.

The Desktop card shows the rows, the bar of a limit, and advice when the reading needs a decision. While the /pitboard pane is open, the Desktop row shows no cards. The /pitboard pane, which either pitboard button also opens, shows every card in the row's order with its explanations; see Open every card with /pitboard, and the pane itself in the CLI and in Desktop in Getting started, step 3.

A reading is calm (grey), watch (amber), or act (red). The table gives the value where each level starts: a percentage for context and limits, and minutes left for the cache, where the level starts below the value. context_pct is Ctx, five_hour_pct is 5h, week_pct is 7d and every model-scoped limit, and cache_1h_minutes_left and cache_5m_minutes_left are Cache with a one-hour and a five-minute TTL.

  • Context also turns act at three turns left or fewer, while auto-compact is on.
  • The five-hour limit also turns act when its Pace is above its Budget, because at that pace it runs out before the reset. With PaceLine's projection, it turns act when PaceLine reports that the window would reach its threshold before the reset. See Colours.
  • The weekly limit and each model-scoped limit use the same levels, from the percentage used only.
  • The cache levels follow from the TTL: watch below the lesser of 15 minutes and half the TTL, act below the lesser of 5 minutes and a fifth of the TTL. The countdown ends 5 seconds before the TTL.
  • An expired cache is blue in Desktop and teal in the terminal, apart from the levels.
  • Hit and the session card have no levels.

Environment variables

Variable Use
CLAUDE_CONFIG_DIRThe Claude Code configuration directory; ~/.claude when unset.
USERPROFILE, HOMEThe home directory for ~/.claude, USERPROFILE first.
PACELINE_STATE_DIRPaceLine's state directory, where the limits file lies.
CLAUDE_CODE_ACCOUNT_UUID, CLAUDE_CODE_ORGANIZATION_UUIDThe signed-in account, which the Claude Code Desktop host passes to its session. When both are set and the account variable is a UUID, the row shows that account's partition of the limits file; otherwise the account comes from .claude.json.
LC_ALL, LC_TIME, LANGThe locale for weekday names, read in this order on every OS; C and POSIX are skipped. When none gives a locale, PitBoard asks pwsh.
CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENSThe context size from which idle compaction applies, for the Idle compact row. Claude Code's minimum is 100,000 and its default 200,000; a positive whole number below 100,000 counts as 100,000, and any other value gives the default.
DISABLE_AUTO_COMPACTWhen set to 1, true, yes or on, auto-compact and idle compaction are off, and the Idle compact row reads off.

PitBoard reads these variables from the environment Claude Code started in.

Files read

<config> is $CLAUDE_CONFIG_DIR, else ~/.claude. <state> is $PACELINE_STATE_DIR when it is set and not empty, else <config>/state/paceline, the rule PaceLine uses.

File What PitBoard takes from it When
<config>/settings.jsonadvisorModel; the effort level for /effortAt session start, after each turn, every 20 seconds, and after /advisor and /effort
<state>/rate-limits.jsonFive-hour and weekly readings and model-scoped limits, from the partition of the signed-in accountAt session start, after each turn, and every 20 seconds
<state>/rate-limits.history.jsonl and its rotated .1Earlier readings of the signed-in account, for PaceAt session start
<config>/.claude.json, else ~/.claude.jsonThe signed-in account, as a 16-hex-digit SHA-256 key of oauthAccount.accountUuid and organizationUuid; nothing else in the fileWith the limits file
<state>/five-hour-burn-<key>.jsonPaceLine's projection of the five-hour limit to its threshold: the account, window and percentage it was computed for, the rate, the budget rate, the threshold and the time it is reached, and whether the burn is limitedWith the limits file
<config>/projects/<start directory>/<session id>.jsonlCache reads and writes since the last compaction; the TTL; the last request's timeAt session start, after each turn, and after /clear or a resume
  • The limits file and its history are PaceLine's; PaceLine's reference describes their format. PitBoard keeps the key of the account and the samples it stores together, and drops stored samples that belong to another account.
  • .claude.json is Claude Code's own file, in <config> when CLAUDE_CONFIG_DIR is set, else in the home directory itself, never in ~/.claude. PitBoard reads it, never writes it, and keeps only the key.
  • The transcript folder is the start directory with every character other than a letter or digit turned into -. When the transcript is not there, PitBoard searches every folder under <config>/projects.
  • Claude Code reads a file of up to 4 MiB for a plugin. For a longer transcript, PitBoard reads its last 4 MB through node.
  • Until the first request reports an effort level, the effort comes from modelSettings or effortLevel in the settings Claude Code loaded.
  • The burn file is PaceLine's too: PitBoard reads five-hour-burn-<key>.json for the signed-in account's key and no other burn file. A key that cannot be read for a moment keeps the last one, and with no key at all no file is read. Its format is the contract. PitBoard uses a file for the 5h limit card only while it is at most 3 minutes old and matches the signed-in account, the window and the percentage on the row. A missing or unreadable file draws the row from PitBoard's own readings.

PitBoard runs these processes, in the CLI and in Desktop:

Command For
git branch --show-current, in the start directoryBranch, at session start and after each turn
pwsh -NoProfile -Command (Get-Culture).NameWeekday names in the OS locale, once per session, only when LC_ALL, LC_TIME and LANG give no locale, on any OS
node -e <tail reader> <transcript>A transcript over 4 MiB

PitBoard writes no file and changes no setting. It keeps the five-hour readings of the last 3 hours and the weekly readings of the last 6 hours in the store Claude Code gives each plugin, so a new session starts with a Pace.
