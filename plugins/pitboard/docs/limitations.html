PitBoard limitations

What PitBoard cannot do, grouped by where you meet it. Each entry says what you see and what still works, with a link to the page that explains the workaround. For how the numbers are made, see How PitBoard works.

Accounts and logins

Limits need a claude.ai subscription login

PitBoard takes the five-hour and weekly limits from what Claude Code reports, and from PaceLine's limits file. A session that uses an API key, or a login without Pro or Max usage limits, gets no limit readings. Sessions through a gateway, Amazon Bedrock, or Google Vertex AI are not tested; without limit readings they show none either.

the 5h gauge stays empty, 7d is missing from the row, and the 5h limit card says No reading yet.

context, cache, and the session card. See Limits stay empty.

Two accounts in one configuration directory show their own limits, with gaps

PaceLine keeps the readings of each account in a partition of its own in the limits file, and PitBoard draws the partition of the account that is signed in, found from the variables CLAUDE_CODE_ACCOUNT_UUID and CLAUDE_CODE_ORGANIZATION_UUID that a Claude Code Desktop host passes to its session, else from Claude Code's .claude.json. A Desktop session and a terminal session on different accounts at once each draw their own. After a /login in a session without the variables, the row follows the new account within about 20 seconds, and the samples behind Pace of the old account are dropped. In a session with the variables, a /login or /logout marks the account unknown until the session restarts. Some gaps remain:

  • A reading with no account, from an older PaceLine or another writer, sits in a partition that belongs to no account. PitBoard draws it when the signed-in account has no partition yet, and marks it.
  • When .claude.json is missing, does not parse, or names no account, PitBoard cannot tell whose figures the file holds. It draws the top level of the file, which is the newest partition, and marks it. If the account was known a moment before, PitBoard keeps its samples and takes a different account only when .claude.json names one.
  • Figures from a file of unknown account show no Pace, and they are not added to the samples behind it.
  • The session's own limits, which Claude Code reports with each reply, are never marked. For the turn after a /login, they may still be the old account's.
  • A /login in another open session can misfile PaceLine's readings for a while, as PaceLine's limitations describe.

the 5h limit, Week and model-scoped limit cards show an Account row with unknown whenever a figure of the limit comes from a file whose account is not known. The row shows no mark while the figures are the account's own.

a Desktop session and a terminal session on different accounts need no second directory. To run two terminal sessions on different accounts, give each account its own configuration directory, as the next entry describes. PaceLine's limitations give the detail. See also Use two accounts on one machine.

Each configuration directory has its own row data

A session reads its settings and its transcript under its own configuration directory, and PaceLine's limits file under <config>/state/paceline unless PACELINE_STATE_DIR is set. <config> is $CLAUDE_CONFIG_DIR, else ~/.claude.

a session of one configuration directory never shows the readings of a session of another.

see Move the state directory.

Surfaces

The Claude mobile app has no row

The row draws only in the CLI and in Desktop. The Claude mobile app has no row.

no row in the Claude mobile app.

/pitboard opens a pane with every card on any surface. See Open every card with /pitboard.

Some readings need git, pwsh, or node

PitBoard runs git for Branch, pwsh for weekday names in the OS locale when LC_ALL, LC_TIME and LANG give no locale, and node for a transcript over 4 MiB. Each helps only when it is on the PATH of the environment Claude Code starts in.

without git, no Branch row; without pwsh, weekday names in the default locale of Claude Code's plugin runtime; without node, the transcript readings of a long session stay n/a.

every other reading. See Requirements.

The Desktop row gives way to a survey

In Claude Desktop before 2.37337.1 (2026-10-13), a survey above the prompt took the row's place: while it showed, PitBoard drew no row there. Since 2.37337.1 the survey appears inline with the session messages and scrolls with them (the maintainer's observation). Claude Desktop 2.42304.0 passes no survey to the row (hasSurvey is always false in its bundled code), so PitBoard draws its row while the inline survey shows.

in Desktop before 2.37337.1, no row above the prompt while the survey shows.

/pitboard shows every card meanwhile.

Data PitBoard cannot see

Limits while every session is idle

Limits while every session is idle, unless PaceLine's usage-watch is on.

the five-hour and weekly readings stand still, and the row lags /usage.

turn on PaceLine's usage-watch. See Use PitBoard with PaceLine.

Other sessions' readings and model-scoped limits need PaceLine

Other sessions' readings, unless PaceLine records them. Model-scoped limits, unless PaceLine's usage-watch writes them. PitBoard shows them only while the newest exact reading is at most 15 minutes old.

without PaceLine, a session shows only the limits of its own requests; without usage-watch, no model-scoped limits.

see Model-scoped limits.

The Threshold row needs a fresh PaceLine projection

The Threshold row, unless PaceLine's burn file of the signed-in account (five-hour-burn-<key>.json) is at most 3 minutes old and belongs to the signed-in account, the current window and the percentage on the row. PaceLine writes it only while pace is on.

the 5h limit card projects to 100% and shows Runs out, and the limit turns red later, when its own projection reaches 100% before the reset instead of PaceLine's threshold.

turn on pace in PaceLine and keep a session working. See Use PitBoard with PaceLine and Budget, At reset, Runs out.

The advisor shown is the setting

The advisor of the running conversation. PitBoard shows the setting, advisorModel in settings.json.

the advisor on the row follows settings.json, which can differ from the advisor the running conversation uses.

/advisor in this session shows at once.

Desktop reports no pointer movement

Pointer movement in Desktop. Desktop tells a plugin nothing about hover, so a card is the surface's own hover reveal.

a card can stay up after the pointer leaves.

see A Desktop card stays open.

The transcript format is private

A stable transcript format. The transcript is a private file of Claude Code. If PitBoard cannot read it, Session counts only the requests since PitBoard loaded or since the last compaction, and TTL reads 5m?.

Session counts fewer requests, and TTL reads 5m?.

context, the cache countdown, Hit, and the limits come from Claude Code.

Only the last 4 MB of a long transcript counts

For a transcript over 4 MiB, PitBoard reads its last 4 MB through node.

Session counts only what the last 4 MB holds.

Hit for the last turn comes from the session's own requests. See Files read.

Subagents do not show on the row

Subagents' requests and compactions leave the row alone; it describes the main conversation.

a subagent's context, cache, and compactions do not show.

the limits include what subagents spend, since they belong to the account. See Where the numbers come from.

Idle compaction is shown as expected

The ᶻ mark and the Idle compact row say Claude Code is expected to compact a long idle conversation before its one-hour cache expires. PitBoard checks the setting, DISABLE_AUTO_COMPACT, auto-compact, the one-hour TTL and the context size. It cannot see the feature flag Claude Code also consults, and it does not check the surface; the settings reference names a terminal session (Claude Code, settings reference, read 2026-10-15).

the mark and on in the row while a flag or the surface keeps Claude Code from compacting the idle conversation; and off for idleCompaction: false on Claude Code before v2.1.290, which ignores the setting and can still compact.

off and n/a hold for the conditions PitBoard checks, and the figures of the Ctx card are unaffected. See Context and cache.

Where an organization manages Claude Code, PitBoard sees a compaction late

On a Team or Enterprise login, and on a machine with managed settings, Claude Code seats its built-in sec-default guard. The guard keeps compaction events from the hooks module of a plugin you install, and PitBoard updates the row on that event. A fix is planned for a later version.

after a compaction, the context reading keeps its figure from before it until the next request, and Session hits count from before it until the next turn ends. The note that compaction replaced the history and the next turn re-caches it does not show, and Turns left can rest on samples taken before the compaction.

every other reading, and the limits. An administrator can run PitBoard in the organization's tier by naming pitboard@agentpit in managed appendPlugins, or in prependPlugins ahead of sec-default@builtin; the guard does not skip that tier. That relaxes the organization's security settings, so it fits a small team whose owner can decide that, and hardly a large organization. This is from the sec-default README, not tested here.
