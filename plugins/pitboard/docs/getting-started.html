Getting started with pitboard

pitboard draws a status row above the prompt: how full the context is, how long the prompt cache lives, and how fast you spend your usage limits. Grey means carry on.

TL;DRInstall it and start a new session: a row appears above the prompt. Grey means carry on; amber and red say which reading needs you. Pace against Budget on a limit tells you whether it lasts to the reset.

Install

  1. Install the plugin

    /plugin install pitboard@agentpit

    Requires Claude Code 2.1.287 or later. pitboard writes no file, settings.json included.

  2. Start a new session

    The row loads at session start, in the CLI above the prompt's hint line and in Desktop as a band of small gauges. /pitboard opens every reading with its explanation in a pane, the only view in the mobile app.

Four groups, left to right

The same row in the CLI and in Desktop; the row anatomy page explains each reading.

Context

How full the context is, measured against the point where Claude Code compacts it.

Cache

Time left before the prompt cache expires, and how much of the last turn came from it.

Limits

The five-hour and weekly usage limits, and, with paceline's usage-watch on, a weekly limit for one model family.

Session (ⓘ)

Model, effort, advisor, running time and API cost; the branch only in the CLI. A click away in the CLI, on hover in Desktop. While an advisor is set, both rows also show it as its own group between Ctx and Cache, marked (inactive) when it ranks below the main model.

Five terms to know

They appear in the limit cards. Each is computed by pitboard from the readings Claude Code reports.

See them move in the row anatomy page

With paceline

If paceline is installed too, pitboard also reads paceline's limits file. A fresh session then shows limits at once, and Pace has a history from the first draw.
